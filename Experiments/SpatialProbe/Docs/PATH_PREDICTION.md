# 扇形目标路径与触觉对准（build 10）

## 使用

开始采集后，默认开启「预测路径」。设置 → **扇形目标路径与偏航振动** 可分别关闭路径/振动，调整选点半角、到达半径、路径最小总宽度、对准/再提示角度、连线保留时间、前视距离。停止、后台、冻结、追踪异常及热状态 critical 会撤销当前显示/反馈；设置弹窗打开时暂停振动。路径设置跨启动保存。

- **黄色目标环**：选定的远方目标点，不是终点导航。
- **青虚线**：从估计脚下（相机在参考地面的投影）到已观测段的显示连接；近身盲区未验证，不证明地面或净空。真实脚的位置未追踪。
- **黄实线**：当前蓝色地面上生成/重新验证的一条几何预测线。
- **橙虚线**：短时世界坐标历史线，当前未完整重新观测。不是把旧像素贴到屏幕，也不声称当前净空仍然有效。
- **无预测路径**：未确认地面、连续蓝色支持或宽度不足，或追踪/时效不合格。不为画线补齐未知区域。
- 屏幕与俯视图显示同一条预测线；旧版左/中/右多条候选线只在关闭预测线后启用。
- 手机光轴在地面的投影假设为人的前进方向；未估计人体朝向。胸前持机，追踪异常/前向投影近乎垂直时暂停振动，但保留可显示的世界线。

**强振只表示朝向对准预测线，不是“现在安全，可以向前走”。所有行走测试由视力正常人员在受控场地完成，不得无保护盲行。**

## 算法与范围

复用当前 ARKit/LiDAR 或经 ARKit 尺度校验的 CoreML 深度所产生的蓝地面、红障碍，不增加模型、地图依赖或第二个采集会话。不修改既有 LocalGrid 候选/未知状态，不将模型置信替代传感器置信。

### 1. 从蓝色三角面建局部预测图

只栅格化**实际蓝色三角面**，不使用无限地面平面，也不将原生 floor 边界直接填蓝。10 cm 格内 3×3 个分布采样点全部被蓝面覆盖，才得到路径地面支持；这是离散近似，不是连续表面的形式化证明。疑似/确定障碍格不进入路径。

路径独立使用 **minimumWidth=0.50 m 的总宽度**（可调0.50–1.20 m），不再叠加旧候选栅格的身体宽度与余量；旧配置没有此字段时迁移为0.50，其余触觉等偏好保留。0.50 m是实验几何门限，不代表测试者肩宽、携物或动态摆动都适合通过。

中心线以半宽圆盘沿折线扫掠，与障碍/未知**格子方形边界**做距离检查，规划与历史路径否决使用相同定义。恰好相切不算有面积重叠，避免再额外扩大一格：合成的5×10cm走廊能容纳0.50m规划包络，4×10cm不能。实际传感器误差、10cm栅格离散和蓝面稀疏仍会影响判断，不能用这一测试宣称实物0.50m必然通过。

这比旧版“全身体高度每个体素均具净空证据”的候选判定更适合**实验预测线**，但仍不代表已经证明身体净空；玻璃、落差、细杆、尚未进入视野的悬空物仍可能漏检。原候选栅格/通道的严格净空判定保留，未被预测线改成可通行。

### 2. 扇形内最远可达位置＋固定世界目标

将“夹角45°”解释为正前方**左右各45°，总张角90°**（设置可调半角15–75°）。候选目标必须在扇形与当前蓝地面支持的交集内。默认分析范围仍为**前方4m、左右各1.5m**，新目标再限制于4m平面径向距离内；并非整个90°视锥都有有效深度，也不在无限远平面上虚构目标。

1. 从相机地面投影发射离散径向探查，每条射线只连接第一个足迹可用格，不越过已遇到的支持区域跳到远处孤岛。连接可以经过初始未知盲区，**仅画青虚线**，但有已知障碍时也不可连接。
2. 对有蓝面支持且满足宽度的格子执行一次有界、8邻域 **Dijkstra 搜索**，允许横移/绕行，不再受逐行前进限制；斜向移动的两侧格也必须可用，防止穿角。
3. 在所有可达目标中，直接最大化**相机地面投影到目标的平面欧氏距离**；不再取前向z带宽，也不比较是否靠近正前方。相同距离仅用较短路线代价和固定格子索引作确定性破同分，不用角度排序。不是通过故意绕远增加“目标距离”。
4. 回溯路径后用带半宽扫掠碰撞检查的 string-pulling 简化折线，尽量绘成直线；遇到障碍绕行，禁止用不受约束的样条穿红区或未知。实线内部不跨未知缺口。
5. 显示：估计脚下→青虚线→已观测黄实线→黄色目标环。`PredictedPath.points`和`length`只包含已观测段，不把青虚线计入已观测长度。显示/日志另记目标距离、入口距离。

AR投影使用齐次图像变换，让GPU对穿过相机近平面的连接正确裁剪；不会为屏幕显示脚下而拉伸画面或伪造屏幕坐标。脚下在摄像头视野外时，只能显示连线进入画面的部分。虚线按实际米制长度切分（22cm周期、13cm实段），即使直线只有两个端点也保持虚线。

### 3. 固定目标与连线证据分离

- `FixedPathGoal`保存世界点、ID、epoch、选择时间、地面参考和最大距离；`PredictedPath`独立保存可视路径及最后验证时间。
- 一旦选中，**新蓝面显示更远区域也不移动目标**。可沿原路线裁去已走部分，必要时重新搜索到同一个精确世界点，不把目标吸附到新栅格中心。
- 默认距目标**0.35m以内**判为到达（可调0.20–0.75m）。这是相机地面投影，不是足部定位；释放后如有有效数据可立即选下个目标。
- 范围基于当前相机的地面前向和目标距离：默认±45°/4m。退出采用**额外5°、0.2m余量，持续0.3秒**，避免边界抖动换点。超出显示边界立即停振/隐藏旧线；确认越界后才释放目标。手机近乎垂直时无法计算方向，暂停方向判定，仍检查距离。
- 暂时地面数据不足：连线最多保留**2s**（可调0.5–5s），超过250ms改为橙虚线；过期后**隐藏线并停振，目标意图仍保留**。恢复后重新验证/搜索同一目标；元数据中的固定目标不构成当前几何证据。
- 新障碍阻断旧线或脚下连接：立即撤销原线，优先尝试绕障到同一目标。如果暂时不能找到替代连线，目标仍保留，但停止旧线和振动；只有目标自身足迹被当前障碍占据时才解除目标并在有效数据中重选。障碍优先于路径显示，不用换目标掩盖暂时的路径中断。
- 地面/尺度冲突、追踪异常、会话/参数代次变化、停止/后台/冻结等仍按既有生命周期门控撤销，不能为保持目标而跨越无效AR世界参考。
- 手机在正常追踪时的世界位姿仍可能漂移；固定世界坐标不等于厘米级实际位置保证。

### 4. 前视点跟踪与振动

正常AR追踪转向时，方向提示使用最新位姿，不再因单独的30°/s选点稳定性门限暂停；它不产生新的目标/可通行结论。新目标选择仍要求方向稳定，强振仍需角度窗口内连续0.3s。

参考机器人/自动驾驶的 **Pure Pursuit 前视目标思想**：从相机地面投影找到路径最近位置，沿折线前取 **0.8 m** 目标点（可调 0.4–1.5 m），计算设备地面前向与目标连线的有符号角度。只做方向反馈，不计算转向轮角或接管运动。

- **连线偏左→双短振**：每组两段约60–80ms，间隔90ms；**连线偏右→单长振**：每组约180–260ms。根据角差，重复周期约0.85–0.45s、强度0.30–0.80。是单个振动器的节奏编码，不是左右两个物理振动器；人的触感/辨识度需要真机测试。
- 尚未对准时，角差超出对准窗口就按左右节奏重复；转向换侧立即取消旧方向模式，不排队。
- 默认进入**±5°**并连续稳定**0.3s**，取消方向模式并提交一次**强度1、180ms**的强振。仅判断连线角度，不用横向位置误差阻止角度确认；也不声称人已在路径中央。
- 强振后进入静默锁定，±5°附近小摆动或临时缺帧不重复强振。直到角差达到默认**12°并连续0.25s**才重新进入方向提示；再转回对准窗口才允许下一次强振。
- 对准窗口可调，始终比重新提示门限至少小2°。新目标ID/新会话重置确认状态；同目标重验证/绕障不重置。暂停、打开设置、触觉引擎重置不无故重复已发过的对准确认。
- 路径无效/过期、朝向不可计算、设置打开、关闭触觉或后台立即停播。相邻反馈间隔超过250ms不能算作持续对准/偏离证据。实际使用的是短时模式重复，不创建无限振动或补播旧提示。
- Core Haptics逐段`relativeTime`+`duration`构造模式；异常后2秒退避，最多一组正在播放，单组短于最小重复周期。`submitted_*`只证明API接受请求，不证明用户感知；如提交失败，UI/日志明确报错，不将失败的对准请求锁定为已完成；退避后可重新确认/提交。

参考：R. Craig Coulter, *Implementation of the Pure Pursuit Path Tracking Algorithm*, CMU-RI-TR-92-01 (1992)，CMU Robotics Institute 官方出版页；Core Haptics 使用本机 iOS26.5 SDK 的 `CHHapticEngine`、`CHHapticEvent`、`CHHapticEventParameter` 头文件核实，部署下限仍为iOS17。

## 记录与复现

新增 `path.jsonl`，不保存RGB：

- `phase=prediction`：关联epoch/frame/参数，完整世界路径、来源、最后验证时间，失效/重规划原因，蓝色格数、足迹可用格数、规划耗时，配置快照。build9追加reachableCells、targetBearingDegrees、targetGroundDistance、approachDistance；path记录requiredWidth和footAtPlan。build10追加goal（固定世界点）、goalChangeReason；path的targetRange区分目标范围。
- `phase=feedback`：当前帧、路径ID、前视目标、夹角、横向偏差，触觉请求类型/强度/时长及提交/失败状态；build10追加每段relativeTime/duration/intensity/sharpness（segments），记录左右模式与静默锁定状态。
- `render.jsonl`：`pathID`、`pathVertices`、`pathHistorical`、`pathAge`、`pathApproachVertices`、`pathTargetVertices`，区分“算法有路径”与“真正提交绘制”。
- `scripts/read_diag.py` 汇总路径可用帧、原因、绘制提交数、耗时和触觉请求；不能将触觉请求数当作实际触觉完成数。
- `scripts/replay_monocular.swift DIAG_DIRECTORY --paths`：重放已记录的模型输出与ARKit几何，重新运行尺度校验、几何和路径代码。不会重新运行模型/传感器，不是精度真值或iPhone性能测试；使用默认ProbeParameters，若原记录参数不同需先匹配。

## 验收与限制

单元测试覆盖蓝面/红面隔离、未知缺口、窄通道、足迹膨胀、原始深度否决历史、低置信度不续期、位姿重投影、缓存时限、参数/epoch/乱序隔离、对准一次/滞回/渐强/禁用反馈。必须继续真机受控测试：手机转动但不移动、慢走、局部遮挡、出现纸箱/行人、悬空物、停止/后台、触觉强弱差异以及30分钟热状态。

build9历史对比记录保留于Reports/FAN_PATH_2026-09-27.md；build10的固定目标/方向触觉验证见Reports/FIXED_TARGET_HAPTICS_2026-09-27.md。

仍有无路径帧：蓝面稀疏、未知或新障碍导致支持不足时，不用虚构实线填补。19:05记录离线回放从5/113变为45/113个有预测线分析帧（含短时历史），仅表示同一份输入在新搜索/宽度条件下的覆盖差异，不是安全性或准确度提升证明；详见`Reports/FAN_PATH_2026-09-27.md`。没有路径不代表前方有障碍，有路径更不等于安全。

可重复Metal测试（macOS真实GPU、合成顶点，不是真机画面）：编译`scripts/smoke_path_metal.swift`并链接本地SpatialCore release目标；它直接编译应用shader、验证前向投影/近平面裁剪并输出合成图。所有持续行走、窄实物通道、触觉与动态障碍验收仍需真机测试。
