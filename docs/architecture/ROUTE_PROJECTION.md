# 平面预测延长线

## 行为

- 三维数据仍用于估计地面和检测身体高度范围内的障碍；沿地面规划使用现有 LocalGrid 的二维占用列。
- 沿保留的世界参考方向延长，不因地面采样洞或栅格边界停止。地面参考必须有效。
- 使用随行进滚动的 **20 米绘制窗口**表示持续延伸的路线意图。20 米是绘制长度，不是测量距离；没有在远端设置到达目标。
- 路径宽度沿用 minimumWidth（默认总宽 0.50 米）。使用与原规划一致的扫掠圆盘/方格相交计算，遇到占用格截断。
- 原始深度仍执行最终障碍否决。若发现栅格尚未体现的障碍，本帧预测线撤销；尚未实现这类原始深度障碍的精确截断。
- 正在绕行/侧向规划时不绘制穿过原路线的远距延长线，继续显示既有绕行路线。
- 当前参考丢失、追踪异常、后台、停止或数据超过展示时限时撤销预测线。不会借此放松会话隔离和有效期。
- 当前实现使用现有观测范围内的二维占用图；没有增加远距离传感器覆盖或跨帧大地图。

## 绘制和反馈

黄线/圈为原有观测路径/目标；淡蓝虚线为平面外推。预测线从观测路径末端衔接，没有观测路径时可以独立显示。
未知格不改写为 candidate；悬空障碍仍由三维高度处理后投影进入二维占用列。
预测数据不进入到达判定、语音或振动，不提供“前方畅通”确认。主页面结构不变，仅更新 Dev 图例。

## 模块

- SpatialCore/RouteProjection.swift：二维投影、碰撞截断、展示时效。
- ForwardRoutePlanner：生成独立 PathUpdate.projection；保留原 path/goal。
- PathDrawing：prediction 虚线网格；不在窗口末端生成目标圈。
- Snapshots：跟踪/会话门控；ProbeRenderer：统一世界坐标投影和着色。
- PathUpdate 的可选 Codable 字段进入现有 DIAG / Dev Capture，不新增采集来源。

## build 14：Dev Tag 试验策略覆盖（当前生效）

本节覆盖上文早期预测层的显示/瞬时碰撞策略：
- Dev Tag 的路线输入改为 TemporalOccupancyGrid：同一世界位置连续检测满300ms才成为规划障碍；未满阈值不截断、不绕行。
- 相邻有效分析间隔不得超过200ms。中断、消失、离开本帧栅格或会话重置会重置确认计时；不把数秒后重现的物体算作连续存在。
- 匹配采用15cm世界坐标桶和16cm固定起始位置容差；移动目标不能通过不断移动匹配原点无限续接计时。低速移动仍可能被确认，不推断语义威胁。
- 在私有规划副本内，未确认占用及未知区域按“无确认障碍”的假设搜索；传感器原始栅格、红色障碍图、DIAG仍保持原始测量。红色原始检测可能早于路线绕行出现。
- 不再把当前原始深度绕过滤波再否决Dev路线，否则会重新引入鬼影截断。普通编译仍使用原观测规划及当前深度检查。
- 贪心绕行优先尝试同侧角点和最早回归点，逐段检查已确认障碍与总路径宽度，并删除可直连的中间点；失败回退图搜索。绕行侧保持、3秒主动转向沿用原状态机。
- 当前观测路线与远距外推统一黄色实线；缓存仍为橙色虚线、近身连接为青色虚线。日志仍区分来源。
- 路线是试验性几何输出。ARKit反光/吸光表面的深度准确性会下降，不采用“只有假阳性、无假阴性”的传感器假设；只做受控视力正常人员测试。
