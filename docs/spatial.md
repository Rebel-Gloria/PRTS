# 空间感知

本文说明 `SpatialCore` 如何根据深度数据拟合地面、构建占用栅格并测量障碍距离，以及在无 LiDAR 设备上通过单目深度预测与特征点校准输出估算深度。路线规划与播报策略请参阅[工程架构](architecture.md#避障数据流)。

## 坐标约定

图像和深度像素采用传感器原始方向（`u` 向右、`v` 向下），分析前不做竖屏旋转。ARKit 相机坐标系中 `+x` 向右、`+y` 向上，相机前方为 `-z`；深度 `d` 为沿光轴的垂直距离。

当深度图与 RGB 图分辨率不同时，按像素中心位于整数索引的约定缩放内参：

```text
sx  = depthWidth / rgbWidth
fx' = sx * fx
cx' = sx * (cx + 0.5) - 0.5
```

竖直方向以相同方式计算 `fy'` 和 `cy'`。像素反投影至相机坐标及世界坐标的公式如下：

```text
p_camera = ((u - cx') * d / fx', -(v - cy') * d / fy', -d)
p_world  = cameraTransform * [p_camera, 1]
```

世界坐标与重力对齐（`+y` 向上）。地面平面方程为 `n·p + b = 0`，法向 `n` 朝上。局部地面坐标系以相机在地面上的正投影为原点，相机 `-z` 在地面的投影为前向 `f`，横向 `r` 与 `n`、`f` 正交：

```text
p = origin + x*r + h*n + z*f
```

栅格 `z` 轴表示沿前进方向的距离，数据按由近到远的行、由左到右的列排列。

## 显示映射

Metal 渲染器依据窗口方向构建等比例虚拟视口并应用 `ARFrame.displayTransform(for:viewportSize:)`，RGB 与深度共用同一套 UV 坐标，世界坐标点先投影至相机再应用相同变换。外层 SwiftUI 界面将画面等比例铺满屏幕并裁切左右溢出的部分，该展示裁切不影响内部算法和渲染对齐；调试叠加层按深度绘制，不处理真实物体对叠加层的物理遮挡。

## 地面拟合与保持

地面确认仅采纳 `Float32` 有限值、范围在 0.15–5 m 且 ARKit 置信度为高（`2`）的 `sceneDepth` 像素；缺少置信度或低置信度的像素不计入地面观测。

平面拟合采用固定随机种子的 RANSAC（最多抽样 96 组三点假设），并结合 ARKit 的 `floor` 平面作为先验。候选平面必须同时满足以下条件，且连续 3 帧在相机所在位置处高度差小于 4 cm、法向差小于 3° 时才正式确认（由于世界坐标原点会变化，因此不直接比较常数项 `b`）：

| 检查项 | 要求 |
|---|---|
| 法向倾角 | 与重力方向夹角不超过 12° |
| 相机离地高度 | 0.45–2.3 m |
| 内点距离与数量 | 到平面距离不超过 3 cm，且至少 40 个内点 |
| 支持面积 | 至少 0.3 m² |
| `floor` 先验一致性（有先验时） | 高度差小于 7 cm，且先验中心 35 cm 范围内存在内点 |

### 观测暂时中断时的处理

ARKit 世界跟踪已包含视觉惯性里程计，应用不另行进行 IMU 积分，而是分别检查地面可见性、世界跟踪状态和深度有效性：

| 情形 | 处理方式 |
|---|---|
| 当前帧没有测到可用地面 | 保留上一次确认的世界平面最多 2 s（期间相机总位移 ≤ 1 m，沿法向位移 ≤ 0.35 m）。该平面只是历史参考，不表示地面此刻可见；新表面仍须由当前深度生成 |
| 新平面与保留平面不一致 | 高度差超过 12 cm 或法向差超过 8° 时，撤销保留平面 |
| 当前深度不足 | 相机位移小于 0.75 m 时，将上一帧表面模型以半透明线框保留最多 1 s；线框本身不能作为障碍或路线证据 |

## 占用栅格

栅格覆盖左右各 1.5 m、前方 0–4 m 区域，单元格边长为 10 cm，初始状态为“未知”。算法不对单元格之间缺失观测的区域做插值填补：

| 状态 | 条件 |
|---|---|
| 地面 | 单元格内至少 3 个地面样本，且分布在至少 2 个象限 |
| 障碍 | 至少 3 个点位于地面以上 3 cm 至人体高度之间 |
| 未知 | 采样不足，包括仅有 1–2 个高于地面散点的单元格 |

### 严格通行检查与表面绘制

开发版与离线对照使用的严格检查从地面以上 6 cm 至人体高度按每 10 cm 分层，要求每层均存在超过体素最远视线距离并额外留出 5 cm 余量的有效深度样本，再按身体宽度与余量构造圆形足迹检查几何碰撞（地面以上 0–6 cm 的低矮凸起不纳入该层高检查）。

障碍确认累计 300 ms 的实测时间。短时缺少整帧测量时，同一位置的障碍可以在原有关联时限（0.75 s）内接续，缺测间隔不计时；实测为空则重新计时。前方通道内反复出现但尚未确认的这类障碍，不作为畅通的新证据。未知单元格仍允许作为规划候选（见[工程架构](architecture.md#避障数据流)）。开发版表面模型基于 `256×192` 深度图以步长 2 构建，单帧最多绘制 24,576 个三角面。

## 距离测量

热图显示沿相机光轴方向的深度（单位为米）。障碍距离则沿地面测量：先对障碍栅格做 4 邻接聚类（每簇至少 6 个支持样本），以 10% 分位数估计簇前缘位置，再量取相机地面投影点到簇前缘的距离，栅格量化粒度约 10 cm。

### 无地面时的近障提示

当前帧有可用的实测地面时，沿用原有的障碍确认、距离分级和绕行规则。当前帧没有可用地面时，即使保有历史地面参考，也不发出新的畅通、障碍或绕行提示。唯一例外是相机朝向前方且整幅画面均有近距离证据；此时只允许提示“障碍很近”，不提供方向、绕行路线或方向振动。相机朝地或朝天时不适用此例外。

将同一帧原始 `sceneDepth` 深度图按 **4×3** 分区（4 列、3 行）。每区置信度为高（`2`）且有效光轴深度**严格小于 0.40 m** 的像素数，必须**超过该区全部像素的 2/3**。整幅图中只要有一个高置信度的原生深度读数达到或超过 0.40 m，即否决提示。缺测和低置信度像素仍计入分母，但不算近距证据；通过判定不表示每个像素都已测到。单目预测不能替代原生深度与置信度。

## 结果有效期

| 规则 | 说明 |
|---|---|
| 当前帧结果 | 分析结果最多有效 250 ms。保留历史证据不延长原始帧的有效期 |
| 帧顺序 | 源帧不能晚于显示帧，`epoch` 和参数版本必须匹配，`frameID` 必须递增；绘制前由 `ResultPresentationGate` 再次复核 |
| 短时丢帧 | 没有新的测量帧时，`WaypointSurvey` 只允许在近期实测栅格仍覆盖下一步所需宽度时沿用原路段，不开启新提示或选择新目标。`PathOptions.retentionSeconds` 默认为 2 s，从原观测时间起算。新的相机位姿、空栅格或反馈恢复都不能续期 |
| 跨帧数据 | 单帧栅格仅使用当前深度。地面参考（≤ 2 s）、历史线框（≤ 1 s）与 300 ms 障碍确认窗口各有用途，不能互相替代 |
| 网格时间 | `callbackTime` 为收到回调的时间，旧网格仅作为结构先验 |
| 仅暂停反馈 | 拍照或提问、流式字幕、打开设置及临时失焦不主动重启已运行的 AR 会话，也不延长证据有效期。后台若未发生系统中断，可以保持同一 `epoch` |
| 相机交接与停启 | 读文字交出相机，低视力模式改用普通 RGB 相机。两者都停止空间采集并清空旧结果；恢复空间采集与显式停止后再启动一样，进入新 `epoch`，等待新测量 |
| 系统中断与重新定位 | ARKit 中断时保留运行意图，但立即更换 `epoch` 并撤销旧结果。中断结束不重复启动会话，等待新帧；重新定位期间跟踪不正常时同样不能输出旧结果 |
| 设备发热 | 热状态达到 `serious` 时分析频率降至 5 Hz 以下；达到 `critical` 时暂停分析并撤销输出 |

短时沿用仍要求相机位姿新鲜、跟踪正常，且路线的 `epoch`、参数版本和障碍更新序号有效。收到没有可用地面的新测量时，仍有效的原路线可以继续显示，但不能据此提示转向。若该帧确认整幅近障，则撤下原路线；即使随后丢帧，也不恢复此前的路线或方向振动。恢复时若只测到空地，也不能给旧障碍和绕行目标续期。判断是否离开已测区域看人实际到达的位置，而不是手机朝向；原地转动手机不会单独触发失测提示，走出后站定仍可按原条件提示一次。

## 并发与缓存

AR 回调只负责打包同一帧数据，分析队列采用单槽覆写（新帧替换未处理的旧帧），Metal 着色器在后台编译一次：

| 资源 | 上限 |
|---|---|
| 待处理网格更新 | 按 anchor 合并，最多 32 项 |
| 网格缓存 | 64 个或 32 MiB，超出时丢弃并记录数量 |
| GPU 命令缓冲 | 同时最多 2 个；纹理和源帧保留至命令执行完成 |

## 无 LiDAR 模式

设备不支持 `sceneDepth` 时自动启用无 LiDAR 模式（通过硬件能力检测判定，不提供手动开关）。该模式关闭 `sceneDepth` 和场景网格，仅开启水平与竖直平面检测，通过单目模型估计相对深度并结合特征点校准米制尺度。

> [!IMPORTANT]
> 无 LiDAR 模式仅用于深度热图显示与路线示意。由于没有实测深度与传感器置信度，`VisibilityDepth` 不会将该深度计为已确认净空，`PredictedGeometry` 也会清除所有候选通行单元格。此外，低视力模式会暂停整套 ARKit 与深度计算，不能用于验收无 LiDAR 空间感知。

### 深度模型与米制校准

| 项目 | 规格 |
|---|---|
| 模型与来源 | Apple Core ML 版 Depth Anything V2 Small（`apple/coreml-depth-anything-v2-small`，提交 `cfef6f6f`） |
| 权重文件 | `PRTS/Spatial/Models/DepthAnythingV2SmallF16.mlpackage`（约 49.8 MB，附带许可证与 SHA-256 校验记录） |
| 输入与输出 | 接收 518×392 图像（按模型包实际接口，而非模型卡文字标注的 518×396），输出同尺寸单帧归一化相对逆深度并映射到宽 256 像素的分析图 |
| 计算单元 | `.all`，由系统自动分配 |

应用从当前帧投影 `rawFeaturePoints` 与稳定 `floor` 平面射线交点收集参考深度配对，采用 RANSAC 拟合尺度关系：

```text
1/z = a * ((q - center) / spread) + b
```

每个分析像素最多为尺度拟合提供一票。拟合与回放评分都使用读取深度时的整数像素坐标，不从浮点射线反算，避免在半像素边界把不同采样合并或把一次采样重复计票。单个有效特征点优先于同像素的地面射线；多个有效特征点落到同一像素时，该像素不参与拟合，也不以地面射线替补。单个相对深度值不能分辨遮挡边缘的前后表面。帧间漂移检查仍使用原始特征标识和射线。

只有单帧拟合与连续 3 帧确认同时通过后才输出米制深度；任一帧拟合失败时立即停止输出并重新开始确认，通过确认后仅保留拟合范围附近的深度（最多向外扩展 10%）：

| 检查项 | 单帧拟合门槛 | 连续 3 帧确认门槛 |
|---|---|---|
| 配对数量与分布 | 至少 16 对，覆盖 4×4 分区中的至少 6 个区域 | 上帧参考点重投影后至少 16 个，覆盖至少 6 个区域 |
| 有效范围与斜率 | 参考深度 0.3–8 m，P90 与 P10 之差大于 0.35 m，斜率为正 | — |
| 误差筛选 | ≥ 65% 配对误差小于 15%，残差中位数小于 8% | ≥ 65% 参考点误差小于 20%，残差中位数小于 8% |
| 帧间稳定性 | — | 有 feature ID 时漂移不超过 `max(8 cm, 1.5% 参考距离)`；帧间隔小于 0.5 s 且位移不超过 0.75 m |

### 地面参考与诊断记录

无 LiDAR 模式从 `ARPlaneAnchor` 中筛选地面参考：

| 条件 | 要求 |
|---|---|
| 方向与位置 | 法向朝上，倾角不超过 12°，位于相机下方 0.45–2.3 m |
| 面积 | `floor` 平面至少 0.3 m²，未分类平面至少 0.7 m²；其他分类平面（如桌面）不参与选择 |
| 稳定性 | 同一平面保持稳定 0.4 s；高度变化超过 5 cm 或法向变化超过约 3° 时重新检查 |
| 暂时丢失 | 最多保留 2 s（期间设备位移 ≤ 1 m）；保留的参考仅用于显示，不提供新的拟合配对 |

校准完成前热图标注为“相对深度”，通过确认后标注为“预测深度（米）”。模型不输出传感器置信度，`predictionSupport` 掩码记录的是几何筛选结果。`prediction.jsonl` 记录模型版本、相对深度附件、平面、配对、拟合结果、失败原因和阶段耗时；通过校准的深度写入 `analysis.jsonl` 并标记为预测来源（格式见[开发指南](development.md#自动录制)）。

## 已知限制

- 单一局部平面无法完整表达台阶和坡道过渡，目前尚未实现台阶和落差检测。后续方向为利用 LiDAR 对比相邻支撑面的高度差与边界，区分上台阶、下台阶和未知区域。
- 透明玻璃、反光地面、剧烈光照变化、细杆、低矮障碍、ARKit 平面误分类及机身朝向偏离行进方向，均会降低检测可靠性。
- 无 LiDAR 模式尚未在真机上完成移动、弱光与真实卷尺测距误差验证；上表中的误差比例属于几何筛选条件，不代表实际测距精度。
