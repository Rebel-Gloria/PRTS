# 空间感知

本文介绍 `SpatialCore` 如何根据深度数据确认地面、构建栅格和测量障碍距离，以及无 LiDAR 设备的深度估计方法。路线规划和播报规则请参阅[工程架构](architecture.md)。

## 坐标约定

图像和深度像素使用传感器原始方向，`u` 向右、`v` 向下，分析前不旋转为竖屏方向。ARKit 相机坐标系中 x 向右、y 向上，相机前方为 −z。深度 `d` 是沿光轴的距离，而不是相机到空间点的直线距离。

深度图与 RGB 图分辨率不同时，按像素中心位于整数索引的约定缩放内参。以水平方向为例：

```text
sx  = depthWidth / rgbWidth
fx' = sx * fx
cx' = sx * (cx + 0.5) - 0.5
```

竖直方向以相同方法计算 `fy'` 和 `cy'`。反投影和世界坐标转换如下：

```text
p_camera = ((u - cx') * d / fx', -(v - cy') * d / fy', -d)
p_world  = cameraTransform * [p_camera, 1]
```

世界坐标与重力对齐，+y 向上。地面平面表示为 `n·p + b = 0`，法向 `n` 朝上。局部坐标的原点是相机在地面上的投影；前向 `f` 是相机 −z 方向在地面上的投影；横向 `r` 与 `n`、`f` 都垂直。局部点表示为：

```text
p = origin + x*r + h*n + z*f
```

栅格的 z 轴表示沿前进方向的距离，与屏幕纵坐标无关。栅格数据按由近到远的行、由左到右的列存储。

## 显示映射

渲染器根据窗口方向计算旋转后的画面尺寸，创建同比例的虚拟视口，然后应用 `ARFrame.displayTransform(for:viewportSize:)`。画面等比例放入视口，剩余区域留黑。RGB 和深度使用同一套 UV 坐标；世界坐标中的点先投影到相机，再应用相同的显示变换。

标准界面在 SwiftUI 层将画面等比例铺满屏幕，两侧超出部分被裁切，此调整不影响渲染器内部的映射。空间叠加层用于诊断，不处理真实物体对叠加内容的遮挡。

## 地面确认

分析始终读取原始 `sceneDepth`。有效观测必须满足：Float32 有限值、深度在 0.15–5 m 之间、置信度为高（2）。缺少置信度或置信度较低的像素不会被视为已确认的空地。

地面拟合使用固定随机种子的 RANSAC，最多尝试 96 组三点假设，并结合 ARKit 的 `floor` 平面作为先验。候选平面必须满足以下条件：

| 检查项 | 条件 |
|---|---|
| 法向 | 与重力方向的夹角不超过 12° |
| 相机高度 | 相机位于平面上方 0.45–2.3 m |
| 内点距离 | 到平面的距离不超过 3 cm |
| 内点数量 | 至少 40 个 |
| 支持面积 | 至少 0.3 m² |
| `floor` 先验一致性（有先验时） | 高度差小于 7 cm，且先验中心 35 cm 范围内存在内点 |

地面需要连续 3 次一致才会确认。一致性在相机所在位置比较：高度差小于 4 cm，法向差小于 3°。由于世界坐标原点变化时常数项也会变化，因此不直接比较平面方程的常数项。

### 观测暂时中断

| 情形 | 处理方式 |
|---|---|
| 暂时看不到地面 | 保留最后确认的世界平面，最多 2 s；期间相机位移不超过 1 m，沿法向位移不超过 0.35 m。显示的表面仍由当前深度生成 |
| 新平面与保留平面不一致 | 高度差超过 12 cm 或法向差超过 8° 时，撤销保留的平面 |
| 当前深度不足 | 将上一次的表面模型以半透明线框保留最多 1 s，前提是相机位移小于 0.75 m；不再显示旧的障碍和通道 |

ARKit 世界跟踪已包含视觉惯性里程计，应用不另外进行 IMU 积分。地面是否可见、世界跟踪是否正常、深度是否可靠是三个独立状态，需要分别检查。

## 栅格

栅格覆盖左右各 1.5 m、前方 0–4 m，单元格边长 10 cm，所有单元格的初始状态为“未知”。

| 状态 | 条件 |
|---|---|
| 地面 | 至少 3 个地面样本，且分布在单元格内至少 2 个象限 |
| 障碍 | 至少 3 个点位于地面以上 3 cm 至人体高度之间 |
| 未知 | 不满足以上条件，包括只有 1–2 个障碍点的单元格 |

算法不填补单元格之间缺少观测的区域。

### 严格通行检查

严格检查用于离线对照。它从地面以上 6 cm 到人体高度每 10 cm 分为一层，每层都必须有有效深度证明为空：观测深度需超过该体积可能的最远交点，并额外留出 5 cm。深度空洞、低置信度、画面外区域和遮挡都会导致检查不通过。地面以上 0–6 cm 的低矮障碍不在检测范围内。

候选单元格必须同时具有地面支持和完整高度的通行空间。算法根据身体宽度和余量构造圆形足迹，按圆与方格的实际几何关系，检查足迹是否与障碍、未知或边界外的单元格相交。

> [!NOTE]
> 标准构建的路线规划使用较宽松的规则：只有持续 300 ms 以上的已确认障碍会阻挡路线，未知单元格可以通过。详情请参阅[工程架构](architecture.md#避障数据流)。

表面模型可以绘制蓝色地面、红色凸起和阻挡柱，应用的渲染选项不显示这些图层。表面每帧最多 24,576 个三角面；对于 256×192 的深度图，以步长 2 构建表面。

## 距离

热图显示的是沿相机光轴的深度，单位为米。

障碍距离沿地面测量，从相机在地面上的投影到障碍簇的近侧边缘。障碍按 4 邻接聚类，每簇至少需要 6 个支持样本，并以 10% 分位数估计前缘位置。栅格量化误差约为一个单元格，即 10 cm。

## 结果有效期

| 规则 | 说明 |
|---|---|
| 有效时间 | 分析结果最多有效 250 ms |
| 帧顺序 | 源帧不能晚于显示帧，epoch 和参数版本必须匹配，frameID 必须递增。绘制前由 `ResultPresentationGate` 再次检查 |
| 跨帧数据 | 单帧栅格只使用当前深度。跨帧保留的内容仅包括：最多 2 s 的地面参考、最多 1 s 的历史线框、网格结构先验，以及规划使用的 300 ms 障碍确认状态 |
| 网格时间 | `callbackTime` 是收到回调的时间，不代表三角面最后一次被观测到的时间。旧网格只作为结构先验 |
| 会话重置 | 停止、进入后台、会话中断或重新定位时立即清空结果。重新开始时使用新的 epoch，不拼接旧会话的世界坐标 |
| 设备发热 | 热状态达到 serious 时，分析频率降至 5 Hz 以下；达到 critical 时暂停分析并撤销输出 |

## 并发与缓存

AR 回调只打包同一帧的数据，不执行空间计算。分析队列只保留一帧待处理数据，新帧替换尚未处理的旧帧。

| 资源 | 上限 |
|---|---|
| 待处理网格更新 | 按 anchor 合并，最多 32 项 |
| 网格缓存 | 64 个或 32 MiB，超出时丢弃并记录数量 |
| GPU 命令缓冲 | 同时最多 2 个；纹理和源帧保留到命令执行完成 |

Metal 着色器在后台编译一次。

## 无 LiDAR 模式

不支持 `sceneDepth` 的设备会自动启用无 LiDAR 模式，且无法关闭。应用检查设备实际支持的能力，而不是根据机型判断。

在该模式下，应用使用 Depth Anything V2 根据相机画面估计相对深度，并结合 ARKit 特征点和平面将其换算为米制深度。

> [!IMPORTANT]
> 无 LiDAR 模式仅用于深度显示和路线示意。它不输出确定的障碍距离，不生成候选通道，也不判断台阶和落差：`VisibilityDepth` 不会根据预测深度确认通行空间，`PredictedGeometry` 会清除所有候选单元格。

### 测试方法

在 LiDAR 设备上，可使用启动参数 `--simulate-no-lidar` 模拟无 LiDAR 设备。该选项只改变应用使用的数据，ARKit 底层仍可能使用 LiDAR，因此最终仍需在无 LiDAR 的设备上验证。

切换模式时，应用停止当前的 `ARSession`，清空已有结果后重新启动。无 LiDAR 模式只启用水平和竖直平面检测，不请求 `sceneDepth` 和场景网格。

### 深度模型

| 项目 | 说明 |
|---|---|
| 模型 | Apple 提供的 Core ML 版 Depth Anything V2 Small（`apple/coreml-depth-anything-v2-small`，提交 `cfef6f6f`） |
| 文件 | `PRTS/Spatial/Models/DepthAnythingV2SmallF16.mlpackage`，约 49.8 MB。SHA-256、Apache 2.0 许可证和模型卡位于同一目录 |
| 输入与输出 | 518×392 图像，输出同尺寸的相对逆深度，每帧单独归一化。模型卡标注的 518×396 与模型包不一致，代码以模型包为准 |
| 计算单元 | `.all`，由系统选择 |

图像送入模型前先转正，再等比例缩放并补边，以保留完整的画面边缘。输出转回相机方向后，映射到宽 256 像素的分析图上。

模型输出的单位不是米，必须经过校准才能用于估计距离。

### 米制校准

校准使用两类参考数据：

- 将 ARKit 的 `rawFeaturePoints` 投影到同一帧，得到模型输出值与深度的配对。
- 对于 ARKit 识别为 `floor` 的稳定平面，通过射线与平面的交点补充配对。

应用用 RANSAC 筛选配对后拟合以下关系，并进一步细化。其中 `z` 为深度，`q` 为模型输出，`center` 和 `spread` 用于归一化，`a`、`b` 为拟合系数：

```text
1/z = a * ((q - center) / spread) + b
```

只有单帧拟合和连续帧确认都通过后，应用才输出米制深度。

| 检查项 | 单帧拟合 | 连续帧确认（连续 3 帧） |
|---|---|---|
| 配对数量与分布 | 至少 16 对，覆盖 4×4 分区中的至少 6 个区域 | 上一帧的参考点投影到当前帧后，至少 16 个，覆盖至少 6 个区域 |
| 参考深度 | 0.3–8 m，P90 与 P10 之差大于 0.35 m | — |
| 斜率 | 必须为正 | — |
| 配对误差 | 至少 65% 的配对误差小于 15% | 至少 65% 的参考点误差小于 20% |
| 残差中位数 | 小于 8% | 小于 8% |
| 参考点漂移 | — | 有 feature ID 时，不超过 8 cm 与参考距离 1.5% 中的较大值 |
| 帧间隔与位移 | — | 间隔小于 0.5 s，位移不超过 0.75 m |

当前帧拟合失败时，应用立即停止输出米制深度并重新开始确认，不沿用之前的系数。通过确认后，只保留拟合范围附近的深度，最多向外扩展 10%。

> [!NOTE]
> 以上误差比例是筛选条件，不代表实际测距精度。实际精度需要用卷尺对照测量。

### 地面参考

应用从 `ARPlaneAnchor` 中选择地面参考：

| 条件 | 要求 |
|---|---|
| 方向与位置 | 法向朝上，倾角不超过 12°，位于相机下方 0.45–2.3 m |
| 面积 | `floor` 平面至少 0.3 m²，未分类平面至少 0.7 m²；其他分类的平面（如桌面）不参与选择 |
| 稳定性 | 同一平面保持稳定 0.4 s；高度变化超过 5 cm 或法向变化超过约 3° 时重新检查 |
| 暂时丢失 | 最多保留 2 s，期间设备位移不超过 1 m；保留的参考只用于显示，不提供新的拟合配对 |

未分类平面附近的蓝色区域只表示该位置接近参考面，不表示已确认为地面。

### 显示与诊断

校准完成前，热图标注为“相对深度”；通过确认后标注为“预测深度（米）”。模型不提供置信度，因此置信度图层显示为不可用。`predictionSupport` 掩码记录的是几何筛选结果，不能作为模型置信度使用。

`prediction.jsonl` 记录模型版本、相对深度附件、平面、校准配对、拟合结果、失败原因和各阶段耗时；通过校准的深度写入 `analysis.jsonl` 并标记为预测来源。格式请参阅[开发指南](development.md#诊断记录)。

## 已知限制

- 单一局部平面无法完整表达台阶与坡道之间的过渡，目前没有台阶和落差检测。
- 玻璃、反光、强光变化、细杆、低矮障碍、ARKit 平面分类错误，以及手机朝向与身体朝向不一致，都可能影响结果。
- 无 LiDAR 模式尚未在真机上验证跟踪、显示对齐、移动和弱光下的校准稳定性以及实际测距误差。回放只能检查校准条件，不能证明测距精度。

台阶检测的后续方向：先用 LiDAR 比较相邻支撑面的高度和边界，区分上台阶、下台阶和未知区域，再评估模型补充。缺少深度不能解释为落差，预测的踏面也不能作为可通行的依据。
