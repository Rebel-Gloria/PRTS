# 空间感知

这一章拆解 `SpatialCore` 如何将原始深度图转化为地面模型、三态占用栅格和障碍距离，以及在没有 LiDAR 的设备上如何通过单目深度预测与特征点校准输出估算深度。路线策略与播报规则见[工程架构](architecture.md#避障数据流)。

## 坐标与投影约定

传感器图像和深度图保持原始采集方向（`u` 向右，`v` 向下），分析前不做竖屏旋转。ARKit 相机坐标系遵循右手系（`x` 向右，`y` 向上，正前方为 `-z`），深度 `d` 指沿光轴方向的垂直距离。

当深度图分辨率与 RGB 图不一致时，按“像素中心位于整数索引”缩放相机内参：

```text
sx  = depthWidth / rgbWidth
fx' = sx * fx
cx' = sx * (cx + 0.5) - 0.5
```

`fy'` 和 `cy'` 采用同样规则。像素反投影到相机及世界坐标的变换为：

```text
p_camera = ((u - cx') * d / fx', -(v - cy') * d / fy', -d)
p_world  = cameraTransform * [p_camera, 1]
```

世界坐标与重力对齐（`+y` 朝上）。地面平面记作 `n·p + b = 0`（法向 `n` 朝上）。算法建立的局部地面坐标系以相机在地面的正投影为原点，相机 `-z` 在地面的投影为前向 `f`，横向 `r` 与 `n`、`f` 正交：

```text
p = origin + x*r + h*n + z*f
```

栅格的 `z` 轴始终表示沿地面向前的距离，按由近到远的行、由左到右的列存储。

## 画面显示映射

Metal 渲染器根据窗口方向构建等比例虚拟视口并应用 `ARFrame.displayTransform(for:viewportSize:)`，RGB 与深度共用同一套 UV 坐标，世界坐标点先投影至相机再走相同变换。外层 SwiftUI 界面将画面等比例铺满全屏并裁切左右溢出的边缘，该展示裁切不影响内部算法和渲染几何对齐；调试叠加层按深度和高度绘制，暂不处理真实物理遮挡。

## 地面拟合与跟踪保持

地面分析仅采纳 `Float32` 有限值、范围在 0.15–5 m 且 ARKit 置信度为高（`2`）的 `sceneDepth` 像素，低置信度或空洞像素不参与地面确认。

平面拟合采用固定随机种子的 RANSAC（最多抽样 96 组三点假设），并结合 ARKit 的 `floor` 平面锚点作为先验。候选平面必须同时满足以下条件，且连续 3 帧在相机当前位置处的高度差小于 4 cm、法向夹角小于 3° 才正式确认（因世界坐标系原点可能漂移，不直接比较平面常数项 `b`）：

| 校验项 | 门槛要求 |
|---|---|
| 法向倾角 | 与重力方向夹角 ≤ 12° |
| 相机离地高度 | 0.45–2.3 m |
| 内点距离与数量 | 点到平面距离 ≤ 3 cm，且至少 40 个内点 |
| 覆盖面积 | 支持面积 ≥ 0.3 m² |
| 与 `floor` 先验一致性（如有） | 高度差 < 7 cm，且先验中心 35 cm 半径内存在内点 |

### 观测短暂缺失时的回退

ARKit 内部已集成视觉惯性里程计，应用不再另做 IMU 积分，而是分别追踪“地面可见性”“世界追踪状态”和“深度有效性”：

- **短暂看不到地面**：保留上一次确认的世界平面最多 2 s（要求期间设备总位移不超过 1 m、垂直位移不超过 0.35 m）。若随后拟合出的新平面与保留平面高度差超过 12 cm 或法向差超过 8°，立即撤销保留。
- **当前帧深度不足**：在设备位移小于 0.75 m 的前提下，将上一帧表面网格以半透明线框保留最多 1 s，并停止输出障碍和路线提示。

## 占用栅格与通行检查

分析窗口覆盖机身前方 0–4 m、左右各 1.5 m，划分为 10 cm × 10 cm 的方格，初始状态均为“未知”，且算法不会对缺失区域做插值填补：

| 栅格状态 | 判定标准 |
|---|---|
| 地面 | 单元格内至少 3 个地面采样点，且分布在至少 2 个象限 |
| 障碍 | 至少 3 个点高于地面 3 cm 至人体设定高度之间 |
| 未知 | 采样不足（包括只有 1–2 个高于地面散点的单元格） |

### 严格通行检查与产品策略

开发版与离线对照使用的严格检查会把地面以上 6 cm 到人体高度的空间按 10 cm 分层，要求每一层都由实测深度证明无遮挡（深度值大于该体素的最远视线距离外加 5 cm 余量），并依据身体宽度和余量用圆形足迹做几何碰撞检测（地面 0–6 cm 的极低矮凸起不纳入这一层高检查）。

产品正式构建采用了更平滑的策略：只有持续存在 300 ms 以上的已确认障碍才会阻挡路线，未知单元格可作为通行候选（详见[工程架构](architecture.md#避障数据流)）。开发版表面建模图元则直接基于 `256×192` 深度图按步长 2 抽样生成，单帧上限 24,576 个三角面。

## 距离测量与结果时效

- **障碍距离**：先对障碍栅格做 4 邻接聚类（每簇至少 6 个支持采样），再从相机地面投影点量取到簇前缘（10% 分位数）的沿地面距离，量化粒度约 10 cm。
- **结果有效期**：分析结果最多有效 250 ms；绘制前 `ResultPresentationGate` 会复核源帧时间戳、`epoch`、参数版本和递增的 `frameID`，防止旧帧回跳。跨帧保留的数据严格限定为地面参考（≤ 2 s）、历史线框（≤ 1 s）、网格结构先验和 300 ms 障碍时间窗。
- **性能与热降频**：AR 回调只负责打包快照，分析队列采用单槽覆写防止积压。待处理网格合并上限 32 项，网格缓存上限 64 个或 32 MiB，GPU 同时在途命令缓冲最多 2 个。设备热状态升至 `serious` 时分析降至 5 Hz 以下，达到 `critical` 时暂停分析并撤销引导。

## 无 LiDAR 模式

设备不支持 `sceneDepth` 时系统自动进入无 LiDAR 模式（通过硬件能力检测判定，不可手动开关）。该模式禁用场景网格与深度采集，仅保留水平和竖直平面检测，改用 Core ML 预测相对深度并与特征点校准尺度。

由于缺乏稠密实测深度和传感器置信度，无 LiDAR 模式**仅用于热图显示与路线示意**：`VisibilityDepth` 不会将预测深度计为已确认净空，`PredictedGeometry` 也会清空候选通行格，它无法替代 LiDAR 提供精确测距或通行担保。注意，低视力模式会连同整套 ARKit 一起关闭，不能用来测试无 LiDAR 空间感知。

### 深度预测与米制校准

| 项目 | 规格 |
|---|---|
| 模型与来源 | Apple Core ML 版 Depth Anything V2 Small（`apple/coreml-depth-anything-v2-small`，提交 `cfef6f6f`） |
| 权重位置 | `PRTS/Spatial/Models/DepthAnythingV2SmallF16.mlpackage`（约 49.8 MB，附带许可证与校验清单） |
| 输入输出 | 接收 518×392 图像（按模型包实际接口，而非模型卡文字写的 518×396），输出单帧归一化的相对逆深度并映射回 256 像素宽的分析图 |
| 计算单元 | `.all`，由 Core ML 自动调度 |

模型输出的相对逆深度没有物理单位，程序收集当前帧的 ARKit `rawFeaturePoints` 以及稳定 `floor` 平面射线交点，通过 RANSAC 拟合尺度关系 `1/z = a * ((q - center) / spread) + b`。只有单帧拟合与连续 3 帧一致性检查全部通过后，热图才从“相对深度”切换为“预测深度（米）”，否则立即撤销米制输出重新确认：

| 校验项 | 单帧拟合门槛 | 连续 3 帧确认门槛 |
|---|---|---|
| 参考点覆盖 | ≥ 16 对，覆盖 4×4 网格中至少 6 个分区 | 上帧特征点重投影后 ≥ 16 个，覆盖至少 6 个分区 |
| 有效范围与斜率 | 深度 0.3–8 m，P90 与 P10 跨度 > 0.35 m，斜率为正 | — |
| 误差筛选 | ≥ 65% 配对误差 < 15%，残差中位数 < 8% | ≥ 65% 误差 < 20%，残差中位数 < 8% |
| 帧间稳定性 | — | 特征点漂移 ≤ `max(8 cm, 1.5% 距离)`；帧间隔 < 0.5 s 且位移 ≤ 0.75 m |

地面参考直接从 `ARPlaneAnchor` 筛选（法向倾角 ≤ 12°、相机下方 0.45–2.3 m、`floor` ≥ 0.3 m² 或未分类平面 ≥ 0.7 m²、稳定 0.4 s），暂时丢失最多保留 2 s。`prediction.jsonl` 会完整记录每帧特征点配对、拟合系数与失败原因（格式见[开发指南](development.md#自动录制)）。

## 已知算法与硬件限制

- 单一局部平面模型无法完整表达台阶和坡道过渡，目前没有专门的台阶或落差检测。后续拟利用 LiDAR 对比相邻支撑面的高度差和边界来区分上下台阶。
- 透明玻璃、强反光地面、剧烈明暗变化、细杆、极低矮障碍、ARKit 平面误分类以及手持朝向偏离行进方向，均会降低判断准确度。
- 无 LiDAR 模式尚未在真机上完成弱光、连续走动和真实卷尺测距误差的系统评估（上述校准残差仅为几何筛选条件，不代表实际测距精度）。
