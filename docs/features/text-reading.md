# 文字识别与朗读

三指按住屏幕 0.8 s，App 会使用后置主摄拍照，识别并朗读文字。默认使用本地 MiniCPM-V 4.7，先判断文字所在的物体，再以“你面前的路标上写着……”等句式朗读。

## 操作与会话切换

“设置 → 三指快速朗读面前文字”默认开启。旁白用户通过主按钮的“读文字”自定义操作进入；关闭该设置后，对应旁白操作也会隐藏。

再次三指长按、轻点主按钮或使用旁白两指双击可退出。打开设置、进入后台和来电同样结束识别。进入前若正在避障，先播报“避障已暂停”，停止 ARKit 并切换到主摄；识别期间暂停避障语音与振动，退出后恢复原状态。

## 识别服务

| 服务 | 处理方式 | 失败处理 |
|---|---|---|
| 本地 VLM（默认） | 离线分两次提问：判断物体类型，再转写文字 | 改用 Apple Vision |
| Apple Vision | 系统离线文字识别，不判断物体类型 | 使用统一开头“你面前的物体上写着” |
| 远端 API | 使用智能设置中的联网服务；千问并行分类与转写，其他服务一次请求完成 | 先尝试本地 VLM，再尝试 Apple Vision |

远端识别要求已选联网服务、允许发送照片并配置 API Key；缺少配置时，在拍照前说明原因并结束。千问使用 `qwen3.8-flash` 分类、`qwen-vl-ocr` 转写。DeepSeek 和自定义服务一次完成分类与转写，均等待完整回答后朗读。

## 默认处理流程

相机会在 App 启动时预先配置。进入识别后，收到第一帧才连接预览；10 s 内未收到图像则提示“无法打开相机”并退出。

App 提示拿稳手机，收到第一帧后等待 1 s，让对焦和曝光稳定，再自动拍照、振动并提示“正在识别”。照片最长边缩放到 1280 像素，交给本地模型：

1. 判断文字位于路标、牌子、纸张还是其他物体，只接受这四类回答。
2. 在同一对话中转写照片里的文字；没有文字时回答“无”，不重新编码图像。

第二步按行或句逐步朗读，不必等待全文生成。没有识别到文字时提示“没有看到文字”。本地模型失败后，Apple Vision 识别整张照片，提示语和正文使用同一声音，按顺序朗读。

提示词明确使用“照片里的文字”，避免模型将指令本身当作待转写内容。推理封装在 `</think>` 处停止生成，App 也会丢弃 `<` 之后的额外内容。当前生成上限为 400 个 token，不能据此保证完整覆盖一页密集文字。

## 实现与限制

`PRTS/Features/TextReading/` 中，`TextReadingSession.swift` 协调一次阅读的生命周期；`Capture/TextCamera.swift` 管理主摄；`Services/` 分别维护提示词、答案解析、服务选择和 Vision 识别；`Views/` 管理手势、预览和状态显示。

尚需扩大反光、倾斜、远处小字、手写和密集文字的验证，并检查三指手势与长按停止的交互。已有识别质量和耗时记录统一见[验证结果](../validation.md)。
