# 文字识别

三根手指按住屏幕，App 用主摄拍一张照片，识别后读出来，格式是"你面前的路标上写着：……"。路牌、招牌、纸张、包装上的字都能读。默认用打包在 App 里的 MiniCPM-V 4.7，不联网。

## 怎么用

- **进入**：三根手指在屏幕任意位置按住 0.8 秒。
  - 设置 → "三指快速朗读面前文字" 可以关掉这个手势（默认打开）。下面有小字提示：使用时会暂停语音播报，请在确认环境安全时使用。
  - 打开旁白时，多指手势会被旁白接管，App 收不到。所以主按钮上加了一个自定义操作"读文字"：在主按钮上用转子选择"操作"，上下轻扫找到它，然后双击。关掉三指开关后，这个操作也一起隐藏。
- **识别服务**：设置 → "识别服务"，三选一：

  | 选项 | 怎么识别 | 能说出字写在什么上面吗 | 联网 | 失败时 |
  |---|---|---|---|---|
  | Apple Vision | 系统自带的文字识别 | 不能，一律说"你面前的物体上写着" | 不 | — |
  | 本地 VLM（默认） | 打包的 MiniCPM-V 4.7，分两次问，见下面"流程" | 能 | 不 | 改用 Apple Vision |
  | 远端 API | "服务与 API Key"里选的联网服务。千问：`qwen3.8-flash` 判断写在什么上面，同时 OCR 模型 `qwen-vl-ocr` 照抄，两个请求一起发。DeepSeek 和自定义服务：一次请求同时问分类和原文 | 能 | 要 | 先改用本地 VLM，再不行用 Apple Vision |

  远端 API 要满足三个条件："服务与 API Key"里选的是联网服务（不是"本机（离线）"），打开了"允许发送照片"，保存了 API Key。缺一样，进入时就直接说缺什么，不拍照。远端返回整段答案后才开始读，不是边生成边读。
- **退出**：再三指长按一次，或者轻点主按钮（旁白下是双指双击）。打开设置、切到后台、来电时也会自动退出。
- 如果避障正在运行，进入时会先说"避障已暂停"，读完或退出后自动恢复。读文字期间避障的语音和振动全部停掉，不会插进来打断朗读。

## 流程

1. 停掉 ARKit，改用后置**主摄**（`AVCaptureSession`）。主摄比超广角清楚，小字也读得出来。
   - 相机在 App 启动时就配好。如果等到避障停下后再配，往会话里加相机要等 ARKit 交出相机，实测要 3 到 9 秒，期间屏幕全黑。提前配好后，从按下到出画面约 0.3 秒。
   - 预览画面要等第一帧到了再接上。会话还在配置时接预览，主线程会跟着卡住好几秒。
   - 10 秒内一帧都没有，就说"无法打开相机"并退出。
2. 先说"读面前的文字，请拿稳手机"。第一帧到了以后再等 1 秒，让对焦和曝光稳定，然后自动拍一张，同时震动一下，说"正在识别"。
3. 照片缩到最长边 1280，交给本机模型，分两次问：
   - 第一问：字写在什么上面？只回答路标、牌子、纸张、物体之一。模型要看图，这一步最慢，约 1.3 秒。
   - 第二问：照抄照片里的文字，没有就回答"无"。第二问接在同一段对话后面，不用再看一遍图。
4. 第二问边生成边朗读：第一行或第一句一出来就说"你面前的路标上写着：……"，后面每出一行或一句就接着读。认不出文字时说"没有看到文字"。
5. 本机模型出错时，改用 Apple 的 Vision 识别整张照片，读成"你面前的物体上写着：……"。

所有提示和朗读都走同一个声音，排队一句接一句，不会互相打断。

## 提示词

提示词在 `PRTS/TextReading/TextReadingPrompt.swift`。2026-10-30 在 Mac 上用 App 同一份推理代码（`Vendor/LocalVLM/csrc`）调出来，然后在真机上复核。

测试图：5 张画出来的图（药品说明纸、便利店招牌、绿色路牌、矿泉水瓶、英文提示牌），再加 4 张没有字的实地照片（`docs/reports/evidence/field-2026-10-28/`，裁掉顶部的调试文字）。

| 写法 | 分类 | 照抄 | 没字的照片 |
|---|---|---|---|
| 一次问完，要求两行格式（第一行分类，第二行原文） | 3/5，还会出现"药物"这种不在四个词里的回答 | 好，但会接着编出第二轮回答 | — |
| 一次问完，要求整句"你面前的X上写着：……" | 不按格式回答 | 好 | — |
| 分两次问，分类规则放在系统消息里 | 3/5，路牌说成牌子 | 好 | — |
| 分两次问，分类规则放在问题里，第二问说"照抄上面的文字" | 4/5 | 好 | **4/4 都把问题原样抄了一遍** |
| **分两次问，第二问改成"照抄照片里的文字，没有就回答无"（采用）** | **4/5**，只有矿泉水瓶说成牌子 | 5/5 全对，只漏掉过一次标题 | **4/4 回答"无"** |

经验：

1. **小模型一次只做一件事。**让它同时分类和照抄，它不守格式；拆成两问后两件都做得好。
2. **"上面的文字"有歧义。**模型会理解成"我上面这段话"，把问题抄一遍。要说"照片里的文字"。
3. **分类规则放在问题里，比放在系统消息里准。**
4. 模型偶尔在答完后自己写一个 `</think>` 再编一轮回答。推理代码看到它就停，App 也丢掉 `<` 以后的内容。

## 远端模型对照（2026-10-30）

用 App 的请求格式在 Mac 上直接调接口。5 张画出来的图加 2 到 4 张没字的实地照片。

| 模型 | 分类 | 照抄 | 没字的照片 | 每张耗时 |
|---|---|---|---|---|
| deepseek-flash（一次问完） | 5/5 | 全对 | 第一版提示词下，有一张答成"牌子 /（照片中无清晰可读文字）"，会被读出来。改成"只回答一个字：无，不写分类，不加括号说明"后，4 张里 3 张答"无"，一张读出远处牌子上的"G" | 约 1 秒 |
| qwen3.8-flash（一次问完） | 5/5 | 全对 | 全部"无" | 0.6–2.5 秒 |
| qwen-vl-ocr（只照抄，采用） | 不按格式分类 | 全对 | 4/4 "无" | 约 0.5 秒 |
| qwen3.5-ocr（只照抄） | 不按格式分类 | 全对 | 4 张里有 1 张编出"一级" | 约 0.5 秒 |

- OCR 模型不守"第一行写分类"的格式，所以千问分成两个请求同时发：`qwen3.8-flash` 只回答写在什么上面（5/5 对），`qwen-vl-ocr` 照抄。
- 选 `qwen-vl-ocr` 而不是更新的 `qwen3.5-ocr`：一样快、一样准，但没字时不编字。
- 真机（iPhone 17 Pro Max，`PRTSTests/RemoteTextReadingTests`，走 App 自己的代码）读路牌：DeepSeek 1.2 秒，千问 2.1 秒，分类和文字都对。Key 只在跑测试时从命令行传进去，不进仓库。

## 速度

iPhone 17 Pro Max 真机（2026-10-30，`PRTSTests/PhotoLocalModelTests`）：路牌和招牌两张图，从开始识别到文字生成完毕约 2.3 秒；没字的图约 2.2 秒。因为边生成边读，实际第一句话出来得更早。模型第一次使用时还要多花约 1 秒加载。

## 代码

- `PRTS/TextReading/TextReadingPrompt.swift`：本地和远端的提示词、两次提问、远端答案的拆分、识别服务的选择（`TextReadingService`），以及把生成的文字切成一句一句朗读（`TextReadingAnswer`）。
- `PRTS/TextReading/TextReadingSession.swift`：主摄、拍照、问模型、朗读，以及整个流程的状态。
- `PRTS/TextReading/TextRecognizer.swift`：Apple Vision，模型出错时用。
- `PRTS/TextReading/ThreeFingerHold.swift`：装在窗口上的三指长按识别器，不拦截其他触摸。
- 测试：
  - `PRTSTests/TextReadingAnswerTests.swift`：切句、开头那句话、"无"、多编的一轮。
  - `PRTSTests/PhotoLocalModelTests.swift`：真机上画路牌、招牌和空白图，走 App 同样的两次提问。
  - `PRTSTests/TextRecognizerTests.swift`：Vision 读图。
  - UI 测试 `testTextReadingStartsCamera`（开发版）：先开避障，再用测试指令"读文字"进入，检查 4 秒内有画面帧，读完后避障恢复。

## 还没试过的

- 远端只测了画出来的图和几张实地帧，真实场景的照片还没测。
- 真实场景的照片：反光、斜拍、远处的小字、手写字。
- 一大页密密麻麻的文字：现在最多生成 400 个 token，大约一页。
- 三指手势会不会和主按钮的按住停止冲突。
