# 文案规范

界面文字和语音播报怎么写。用户大多是听，不是看，而且常常一边走路一边听，所以越短越好。

## 原则

1. 先说用户要做什么，原因能省就省。
2. 一句话只说一件事，不用分号串起好几件事。
3. 只说会发生什么，不列不会发生什么。
4. 安全提示集中放在一个地方，不要在每个控件旁边重复免责。
5. 正式版界面不出现内部术语。统一用这些词：相机、画面、深度、地面、障碍、通道、振动。不要用"摄像头""摄像机""前台""epoch""floor""净空""证据""尺度"。
6. 播报有字数预算：避障提示 10 个字以内，状态播报 15 个字以内。动词放前面，不说"请注意""温馨提示"。新播报要在真机上听一遍。

## 现在的播报用语

| 场景 | 播报 |
|---|---|
| 前方没有障碍 | 前方畅通 |
| 有障碍 | 有障碍 / 障碍很近（实测距离小于 1 米） |
| 有障碍，需要转向 | 有障碍，向左 |
| 绕不过去 | 有障碍，无法绕行 |
| 目标不在画面里 | 有障碍，转动手机 |
| 路线提示 | 向左 / 从左边绕 / 向左回原路 / 直走 |
| 候选通道 | 左侧可走 |
| 感知不可用 | 暂时看不清 |
| 相机状态 | 相机已开 / 相机已关 / 正在打开相机 |
| 首页 | PRTS。相机已关，开始在下方。设置在右上角。 |
| 语音开关 | 语音已关 |

避障播报不报距离，只区分"有障碍"和"障碍很近"：测距本来就有误差，用户也用不上具体米数。同一句话只在这两种状态切换时重报，两次播报至少间隔 2.5 秒（`ObstacleRouteAnnouncementPolicy.minimumInterval`）。

权限说明放在 `InfoPlist.xcstrings` 里，中英文各一份。

## 还没改的

- `MonocularDepthProvider`、`SessionRecorder`、`PathHaptics` 里的状态文案还是旧写法。这三个文件要和 `Experiments/SpatialProbe` 的算法逐字节对比，改了文案一致性测试就过不了。
- `ProbeSettingsView` 的参数说明保留了工程写法，只有开发版能看到。
- `Localizable.xcstrings` 里还有十几条旧界面留下的中文 key，源码已经不用了。要在 Xcode 里确认它们显示为 Stale 后再删。
