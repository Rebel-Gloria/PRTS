# 无 LiDAR 模式

没有 LiDAR 的 iPhone 可以使用 Depth Anything V2 模型，根据相机画面估算深度。App 再结合 ARKit 提供的特征点和地面平面，将模型输出的相对值换算为以米为单位的深度。

这些结果用于显示深度和绘制路线示意。目前还不能将它们作为可靠的测距结果，也不能据此确认某个区域可以安全通行。

## 启用条件

如果设备不支持 `sceneDepth`，App 会自动启用无 LiDAR 模式，且无法手动关闭。App 会检查设备实际支持的功能，不根据机型判断。

带 LiDAR 的设备也可以测试这个模式：在开发版设置中打开“模拟无 LiDAR 设备”即可。不过，这个选项只改变 App 使用的数据，ARKit 在底层仍可能借助 LiDAR。因此，模拟测试完成后，还需要在不带 LiDAR 的手机上验证。

切换模式时，App 会停止当前的 AR 会话（`ARSession`），清空已有结果，再重新启动，避免混用切换前后的数据。

在无 LiDAR 模式下，App 只启用水平和竖直平面检测，不请求 `sceneDepth` 深度数据和场景网格。

## 深度模型与图像处理

App 使用 Apple 提供的 Core ML 版 Depth Anything V2 Small。模型来自 `apple/coreml-depth-anything-v2-small`，文件名为 `DepthAnythingV2SmallF16.mlpackage`，大小约 49.8 MB。当前固定使用的仓库版本是 `cfef6f6f2a70783dedc0bfae40cecbc2052285d3`。

模型的 SHA-256 校验值保存在 `PRTS/Spatial/Models/provenance.json` 中，Apache 2.0 许可证和模型卡也在同一目录。

模型接收 518×392 的图像，输出同样尺寸的相对逆深度，并对每一帧分别归一化。**输出值的单位不是米，需要进一步校准才能用于估算距离。** 模型卡中标注的尺寸是 518×396，与实际模型包不一致，因此代码以模型包内的描述为准。

送入模型前，App 会先将画面转正，再等比例缩放并补齐留白，保留完整的画面边缘。模型输出随后会转回相机画面的方向，映射到宽度为 256 像素的分析图上。

Core ML 的计算单元设置为 `.all`，由系统决定使用哪些计算单元。

## 米制深度校准

模型只能给出相对深度。要换算成米，App 需要先建立模型输出值与 ARKit 深度参考之间的对应关系。参考数据有两个来源：

- 将 ARKit 的 `rawFeaturePoints` 投影到同一帧图像上，取得每个参考点对应的模型输出值和深度。
- 对于 ARKit 已识别为地面（`floor`）的稳定平面，通过射线与平面的交点补充参考数据。

App 使用这些配对数据拟合以下关系，其中 `z` 是深度，`q` 是模型输出值，`center` 和 `spread` 用于归一化，`a` 和 `b` 是拟合系数：

```text
1/z = a × ((q - center)/spread) + b
```

拟合先使用 RANSAC 筛选数据，再进一步细化结果。只有当前帧的拟合和连续帧之间的一致性检查都通过，App 才会输出以米为单位的预测深度。

### 单帧拟合的要求

| 检查项 | 要求 |
|---|---|
| 配对数量和分布 | 至少 16 对；将图像划分为 4×4 个区域后，配对数据至少覆盖其中 6 个区域 |
| 参考深度范围 | 0.3–8 m |
| 参考深度跨度 | 第 90 百分位与第 10 百分位之差（P90−P10）大于 0.35 m |
| 拟合斜率 | 必须为正 |
| 配对误差 | 至少 65% 的配对数据，误差小于 15% |
| 内点残差 | 参与有效拟合的数据，其残差中位数小于 8% |

### 连续帧的确认要求

单帧拟合成功后，还需要连续 3 帧都通过检查。App 会将上一帧的参考点投影到当前帧，检查同一场景在前后两帧中的结果是否一致。

| 检查项 | 要求 |
|---|---|
| 参考点数量和分布 | 至少 16 个点，覆盖 4×4 分区中的至少 6 个区域 |
| 配对误差 | 至少 65% 的参考点，误差小于 20% |
| 残差中位数 | 小于 8% |
| 参考点漂移 | 有特征点标识（feature ID）时，漂移不得超过 8 cm 与参考距离的 1.5% 中较大的值 |
| 帧间隔 | 小于 0.5 s |
| 帧间位移 | 不超过 0.75 m |

如果当前帧拟合失败，App 会立即停止输出以米为单位的深度，并重新开始确认，不继续使用之前的拟合系数。通过确认后，也只保留拟合范围附近的深度，最多向范围外扩展 10%。

这些条件用于筛选预测结果的质量，其中的误差比例不能直接当作实际测距精度。实际精度仍需要用卷尺测量并对照验证。

## 地面参考

App 从 `ARPlaneAnchor` 中选择地面参考。候选平面的法向需要朝上，与水平面的夹角不超过 12°，并且位于相机下方 0.45–2.3 m。

App 优先使用已被 ARKit 识别为地面（`floor`）的平面，面积至少为 0.3 m²。未分类的平面也可以作为参考，但面积至少为 0.7 m²。已被识别为桌面等其他类型的平面不参与选择。

同一个平面需要保持稳定 0.4 s，才能作为地面参考。如果高度突然变化超过 5 cm，或者法向变化超过约 3°，App 会重新检查它是否稳定。

如果暂时检测不到平面，App 最多保留原有参考 2 s，期间设备位移不能超过 1 m。保留的参考只能配合当前帧已经校准的深度用于显示，不能提供新的拟合配对数据。

未分类平面附近的蓝色区域，只表示对应位置接近参考面，不表示那里已经被确认为地面。

## 显示结果与功能限制

深度尚未完成校准时，热图标注为“相对深度”；通过确认后，标注改为“预测深度（米）”。

模型不提供置信度，因此置信度图层会显示为不可用。App 另外保存的 `predictionSupport` 掩码记录的是几何筛选结果，不能用作模型置信度。

无 LiDAR 模式目前不输出确定的障碍距离，也不生成候选通道。实现上，`VisibilityDepth` 不会根据预测深度确认某个区域是否有足够的通行空间，`PredictedGeometry` 则会清除所有候选格。这个模式也不判断台阶和落差。

## 诊断与验证状态

`prediction.jsonl` 记录模型版本、相对深度附件、平面、校准配对、拟合结果、失败原因和各阶段耗时；通过校准的深度另写入 `analysis.jsonl`，标记为预测来源。格式和读取方法见[诊断与采集](../diagnostics.md)。

不带 LiDAR 的真机验证尚未完成，仍需确认跟踪、显示对齐、移动与弱光下的校准稳定性，以及实际测距误差。回放只能检查校准条件，不能证明测距精度。验证状态统一记录在[验证结果与已知问题](../validation.md)。
