# 拍照提示词

短按描述时，所有服务商共用一条系统提示词 `PhotoChatProtocol.system`：几条要做的规则、一张不要做的清单、4 条示例。长按提问另有两套，见下面"提问的提示词"。它是 2026-10-28 在 iPhone 17 Pro Max 上用本地 MiniCPM-V 4.6 调出来的（4.6 后来换成了 4.7），之后又在 30 张图上用两个云端模型复核过，结论是保持不变。

## 结构

- **系统消息**：
  - 角色：为盲人描述镜头前方。
  - "要做"规则：先说最近的东西；再说路面；有字才读；方位词和远近词固定几个；一到两句，不超过四十个字。
  - "不要"清单：不指挥往哪走；不说"这张照片"；不编造；不说米数；不说空话。
  - 4 条示例回答。
- **用户消息**：短按发 `描述眼前。`；长按直接发识别出的问题。（2026-10-31 以前长按会加前缀 `简短回答盲人的问题：`，下面 10-29 的评估用的还是这个前缀。）

## 测试方法

- 照片：5 张实地 DIAG 帧，见 `docs/reports/evidence/field-2026-10-28/`。裁掉顶部 32 像素的调试文字后，分辨率是 360×448。
- 对照答案（人工看图）：
  - B3_185：右下角很近有电动车后备箱。
  - B3_205：正前方很近有电动车后备箱，左边停着自行车。
  - B3_209：正前方很近有电动车座椅，左边停着自行车，右边有红色电动车。
  - B3_289：前面有台阶，上去是地铁站入口，入口里有扶梯。
  - B3_301：正前方是向上的台阶，带黄色防滑条，远处有玻璃门和扶梯。
- 工具：`PRTSTests/LocalVLMBenchmarkTests/prompts()`，从 App 的 `Documents/vlm/prompts.json` 读取提示词变体。云端对照用 `promptsCloud()`，要求手机上已经存了某个服务商的 Key（当时没有 Key，所以没测云端）。

## 本地模型上的结果

| 变体 | 正前方很近的物体（3 张） | 编造 | 首个 token |
|---|---:|---|---:|
| A 原提示词 | 0/3 | 少；但复读"最重要的是" | 约 0.25 s |
| B 规则 + 占位符句式（`[物体]`） | 3/3 | **严重**：四种句式全部填一遍，编出"禁止停车""向下的台阶""CHINA" | 约 0.35 s |
| C 规则 + 具体示例 | 2/3 | 少；但会说"右边可以往前走"，205 和 209 都说错了 | 约 0.35 s |
| D 同 C，全部放在用户消息里 | 2/3 | 多："前景是石板地，可能挡路""右边有门" | 约 0.35 s |
| **C2** C 加"不指挥方向""没有字就不提"（采用） | **3/3**，另外 185 也说出"很近" | 未见危险编造；会多说"没有台阶"这类话 | 约 0.35 s |
| C3 C2 改成"有字就读""不说没有、看不清" | 1/3 | **严重**：编出"超市"招牌、"台阶和坡" | 约 0.35 s |

## 经验

1. **规则和负面约束有用。**加上"先说最近的东西"，加上"画面下方的大物体通常贴在面前"这条判断方法，近处物体从 0/3 提到 3/3。
2. **小模型不要给占位符模板。**它会把每种句式都填一遍。给具体示例，并写明"只学句式，不要照抄内容"；示例内容不要和测试照片里的东西重合。
3. **规则放系统消息，比放用户消息效果好。**
4. **负面约束要写成"不提"，不要写成"不说某某词"。**C3 写了"不说没有、看不清"，反而引出更多编造。"有字就读"比"有字才读，没有就不提"更容易让模型编出招牌。
5. **不让模型指挥方向。**它判断从哪边能绕过去经常判断错，而绕行方向本来就该由 LiDAR 避障决定。描述只说东西在哪。
6. 代价：系统提示词让本地首个 token 慢了约 0.1 秒。对云端来说，多出的几百个 token 可以忽略。

## 云端模型对照（2026-10-29）

- 用 codex 的服务商测了 `wb/deepseek-v4.1-flash` 和 `gpt-6-luna`，作为 App 里 DeepSeek 和强模型的代表。千问不在这个服务商里，没测。
- 题库：5 张照片，每张有一次短按描述，再加两个长按问题，共 15 题。问题里有陷阱题，比如画面里没有牌子却问"牌子上写的什么？"，或者问"前面能走吗？"看模型会不会指挥方向。

| 现象 | 旧提示词 | 新提示词 |
|---|---|---|
| DeepSeek 在 209 问"有没有东西挡着我" | "前方没有明显障碍物"（**危险漏报**） | "正前方很近有个大圆顶物体挡着" |
| "前面能走吗？" | DeepSeek 说"能走…请小心"，GPT 说"建议靠左绕行" | 两个模型都只说东西在哪 |
| 回答长度 | 常有 60–90 字 | 基本在 40 字以内 |
| 示例诱导 | — | 第一版示例里有"垃圾桶""向下的楼梯"，DeepSeek 就把外卖箱说成"垃圾桶"、把向上的台阶说成"向下"。已换成"椅子"，并删掉楼梯示例 |
| 陷阱题"牌子上写的什么" | 都答对 | 第一版 GPT 答"看不清牌子上的字"；补了第 6 条规则后，两个模型都答"没看到牌子" |
| DeepSeek 台阶方向 | 不说方向 | 去掉示例后，301 仍有一半回答说成"向下"；规则已改为"看得清方向时才说" |

- 结论：示例里的名词和方向词会直接诱导模型，所以示例应选与街景差别大的内容，并且不带方向。

## 30 张图正式评估（2026-10-29）

完整报告见 [2026-10-29 提示词评估](../reports/2026-10-29-photo-prompt-eval.md)，题库和原始结果在 `Experiments/photo-prompt/`。

- 30 张实拍帧（20 张用来调提示词，10 张留出验证），每张有一次短按描述和两个长按问题。三分之一是陷阱题。每题每个模型跑 3 次，共 1440 次请求。
- 三轮改写都没有在两个模型、留出集上同时变好。**结论：当前提示词保持不变。**
- 当前提示词的致命错误（编造、方向说反、指挥通行、漏掉贴近的东西）：

| 模型 | 调优集 | 留出集 |
|---|---:|---:|
| gpt-6-luna | 4/180 | 1/90 |
| DeepSeek V4.1 Flash | 31/180 | 0/90 |

- **DeepSeek 的已知风险：把向上的台阶说成向下。**C_B3_301 这张图里，9 次回答说反了 6 次。专门写方向判断规则也没修好，GPT 则一次都没说反。如果用户选 DeepSeek，台阶方向不可靠。
- DeepSeek 在陷阱题上更容易给出"能走"之类的通行许可，或者编出牌子上的字。

## 提问的提示词（2026-10-31）

提问多半是听完一句描述后追问细节，比如"是什么颜色的猫""那个人穿什么"，问能不能走只是其中一种。所以提问不再用描述的提示词，改用两套专门的：

- **千问和 DeepSeek：`questionSystem`。**比描述放得开：颜色、样子、材质、品牌、穿着、数量、文字都能答，也可以翻译、解释用途。规则只留这几条：最多三句，第一句直接回答；没有就说没看到，看不清或一张照片看不出来就直说；方位和远近用固定的词；问能不能走时不说能或不能，也不出主意。
- **本机 MiniCPM-V：`localQuestionSystem`。**小模型守不住太开放的提示词，所以只在描述的提示词上改：开头说明用户已经听过描述、多半想问细节；加一条"问颜色、样子、穿着、数量时说清楚细节"；"一到两句"改成"最多三句"；示例换成问答，其中一条是"能往前走吗"的示范回答。
- 两套都要求最多三句话，代码里也截到第三句（`PhotoChatProtocol.threeSentences`）。

测试：38 个问题。题库里 12 张实地帧的 24 个长按问题，加 6 个开放问题（画出来的药品说明、矿泉水瓶、英文提示牌、便利店招牌、路牌，以及地铁站入口），再加 8 个追问细节的问题（衣服、颜色、数量、椅子什么样、地毯花纹、台阶几级）。云端在 Mac 上直接调接口，本机用 App 同一份推理代码在 Mac 上跑。

| | 旧做法（描述提示词 + 前缀） | 新提示词 |
|---|---|---|
| 千问：追问细节 | — | 8 题都答出颜色、穿着、数量，比如"深灰色短袖，袖子上有荧光黄条纹，浅蓝色牛仔裤" |
| 千问：通行题 | — | 不说能或不能。第一版写了"这些由避障功能负责"，它就照着说"能不能走得问避障功能"，已删掉 |
| 千问：看不出来的 | — | "一张照片看不出来扶梯往哪边运行" |
| DeepSeek：追问细节 | — | 都答得出 |
| DeepSeek：通行题 | — | 规则放宽后会出主意（"往左边靠一点就能让开他""缺口够宽，能走人"），规则改成"也不出主意"后少了，但没断 |
| DeepSeek：台阶方向 | 301 说成向下 | 还是说成向下；在一张全黑的照片上还编出过"一级向下的台阶"一次 |
| 本机：追问细节 | — | 穿着、椅子格子布、地毯颜色、台阶三级黄边都答对；数自行车数少了 |
| 本机：8 个通行题里给出通行许可 | 4 个 | 3 个（"能走""应该没问题"） |
| 本机：便利店"晚上开门吗" | 答错 | 仍答错，说"没看到晚上开门的信息" |

结论：

1. **千问在提问上最稳。**DeepSeek 的老问题（台阶方向、通行许可、编造）在提问时也在。
2. **本机模型答细节可以，答能不能走不可靠。**提示词只能少一点，去不掉，能不能走要交给 LiDAR 避障。
3. **提示词里的话会被原样复述。**写"离用户最近"，本机就说"离用户最近的是……"；写"由避障功能负责"，千问就说"得问避障功能"。
