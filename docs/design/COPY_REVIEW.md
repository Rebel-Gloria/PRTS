# 文案审查：冗余和"不像人话"的地方（只出方案）

日期：2026-10-28。范围：Swift 源码里写死的中文（共 317 处）、`Localizable.xcstrings`、`PRTSInfo.plist` 的权限说明，以及语音播报。
本轮只出方案，不改任何文案。拍照提示词受 build21 的提示词契约测试保护，修改前要先更新契约。

## 一、问题类型

### 1. 免责声明塞进了每一个界面

同一层意思在多个地方反复出现，用户每一屏都要读一遍"这不代表什么"：

| 位置 | 现在 |
|---|---|
| `SessionRecorder.swift:119` | 实验验证，候选通道不等于安全路线 |
| `HomeDemoOverlay.swift:60` | 来源：Core ML 预测＋原生尺度校准（非LiDAR实测） |
| `ProbeSettingsView.swift:20` | ……没有传感器置信度，可绘实验预测线，但不授权已验证净空通道。 |
| `ProbeSettingsView.swift:63` | ……不补遮挡背面，不保证物体与地面接触。……俯视图仍保留未知状态。 |
| `MonocularDepthProvider.swift:27-29` | 原生 floor 参考（非净空证明）/ 待确认水平面（非 floor 分类）/ 短时参考（非当前地面观测） |

**建议**：安全边界只在"能力与边界"一节集中说一次，其他地方只写正面事实。例如"来源：Core ML 预测（已校准）"，不再加括号否认。

### 2. 用否定句解释"不会发生什么"

GPT 很喜欢先列出所有"不会"，再说"会"：

- `DemoOptionsView.swift:15`：只隐藏 RGB 画面；相机采集、空间感知、路径计算和 DIAG 继续运行。关闭后仍可在深色背景查看叠加层。停止采集请使用主页面停止按钮。
  → **改为**：只隐藏画面，后台照常工作。
- `DemoOptionsView.swift:34`：关闭叠加层或路径显示不停止分析，也不关闭方向振动。表面建模开启时替代……振动请在触觉和路径设置中调整。
  → **改为**：只影响显示，不影响分析和振动。
- `SettingsView.swift:21`：仅控制调试界面显示，不停止空间计算、方向反馈或日志记录；录像提示不受这些开关影响。
  → **改为**：只控制调试信息是否显示。

### 3. 一句话塞进好几个分号

中文 UI 很少这样写，读屏时也很难断句：

- `SettingsView.swift:29`（开发采集说明，一共 4 个分句、2 个分号、1 个括号）。建议拆成三行列表：保存什么 / 不保存什么 / 什么时候自动关闭。
- `ProbeViewModel.swift:130`：相机权限未授权。请在系统设置中允许相机访问；没有采集传感器数据。
  → **改为**：没有相机权限。请到"设置"里打开。
- `ProbeSettingsView.swift:78`：局部范围：前4 m／左右各1.5 m；栅格10 cm；仅高置信度建立肯定证据；最多250 ms结果年龄。更稀疏采样可能只得到更多未知，不会补洞。

### 4. 术语混用，用户看不懂

- 同一个东西有三个名字：**摄像头**（状态、播报）、**相机**（权限）、**摄像机**（设置、开发采集）。建议统一叫"相机"。
- 内部术语直接暴露给用户：前台、epoch、floor、sceneDepth、DIAG、RGB、证据、净空、尺度。产品界面里应该只出现"画面""深度""地面""障碍""通道"。开发版界面可以保留术语，但要和产品界面分开。
- `ProbeViewModel.swift:129`："已授权；请返回前台后点击开始。"普通用户不知道什么是"前台" → **改为**："已授权，回到 PRTS 后点'开始'。"

### 5. 语音播报偏长

播报是给正在走路的人听的，越短越好：

| key | 现在 | 建议 |
|---|---|---|
| `speech.camera.permissionDenied` | 摄像头权限被拒绝。请在 iPhone 设置中允许摄像头权限，然后重试。 | 没有相机权限，请到设置里打开。 |
| `speech.home` | PRTS 首页。%@。%@。"设置"按钮在右上角。 | PRTS。%@。%@，设置在右上角。 |
| `speech.settings.summary` | 设置。语音播报已%@。播报速度为%@。%@。触觉反馈已%@。 | 设置。语音%@，语速%@，%@，振动%@。 |
| `ObstacleRouteAnnouncementPolicy` | 前方无障碍，请调整手机方向 | 前方无障碍，请转动手机 |
| `PhotoDescriptionCoordinator.swift:131` | 请允许麦克风和语音识别，然后重新长按 | 需要麦克风权限，允许后再长按 |

原则：空间提示控制在 10 个字以内，状态播报 15 个字以内；动词放在前面；不说"请注意""温馨提示"这类空话。

### 6. 写错了或会误导用户的文案

- `home.command.placeholder`："测试指令（例如：开始导航）"，但实际只支持"开始/停止/状态"。说"开始导航"会得到"当前只支持……"。建议把例子改成"开始"。
- `home.settings.button` 的英文写成了 "Setting"。
- `NSCameraUsageDescription` 是英文，另外两条权限说明是中文，系统弹窗时语言不一致。建议都放进 `InfoPlist.xcstrings`，中英各一份。
- 拍照提示词（`PhotoChatProtocol.swift:8`）："简短、凝练、易理解"三个词意思重复；"不要加入无关细节控制在一句到两句话内"中间缺了标点。建议改成："请为盲人用一两句话描述这张图：主要物体或人在哪里、什么方向、离多远。不要提无关细节。"（需要同步更新契约测试。）

### 7. 已经没有用的文案

`Localizable.xcstrings` 里有 19 条确认没有任何引用的 key，本轮已经删除（例如 `settings.runtime.*`、`camera.error.cannotAddInput`）。
另外还有十几条中文 key 是旧版界面留下的长句，例如"扇形目标路径与偏航振动""黄圈：远端目标；黄实线……"。它们的源码已经不存在，建议在 Xcode 里打开 String Catalog，确认显示为 Stale 后删除。

## 二、改写原则（以后写文案也按这个来）

1. 先说用户要做什么，再说原因；原因能省就省。
2. 一句话只讲一件事，不用分号把几件事串起来。
3. 安全提示集中放一处，不要在每个控件旁边重复免责。
4. 只写"会发生什么"，不要列"不会发生什么"。
5. 产品界面不出现内部术语，统一使用一份术语表（相机、画面、深度、地面、障碍、通道、振动）。
6. 播报文案按字数预算写，并且要用真机朗读试听。

## 三、实施建议

- 第一步：只改第 4、6 类（术语统一、错误文案）。交互不变，风险最低。
- 第二步：精简设置页和开发页的说明文字（第 1、2、3 类）。可以和无障碍方案的 A3（设置页本地化）合并成一次提交。
- 第三步：精简语音播报（第 5 类）。播报节奏会因此变化，需要视障测试员试听确认。
- 拍照提示词单独提交，同时更新 `PhotoDescriptionTests` 里的契约。

## 第二轮（2026-10-28）：实时语音再压缩

避障播报不再说距离，只分"有障碍"和"障碍很近"（实测距离小于 1 米）。测距本来就不准，用户也不需要具体米数。

| 场景 | 之前 | 现在 |
|---|---|---|
| 前方无障碍 | 前方无障碍 | 前方畅通 |
| 有障碍 | 前方障碍，约 1.4 米 | 有障碍 / 障碍很近 |
| 有障碍并要转向 | 前方障碍，约 1.4 米，向左转 | 有障碍，向左 |
| 无法绕行 | 前方障碍，约 1.4 米，暂无绕行路径 | 有障碍，无法绕行 |
| 目标不在画面里 | 前方障碍，约 1.4 米，请转动手机 | 有障碍，转动手机 |
| 路线提示 | 向左转 / 从左侧绕行 / 向左，回到原路线 / 继续直行 | 向左 / 从左边绕 / 向左回原路 / 直走 |
| 候选通道 | 左侧有通道 | 左侧可走 |
| 感知不可用 | 感知暂不可用 | 暂时看不清 |
| 相机状态 | 相机正在运行。/ 相机未开启。/ 正在启动相机。 | 相机已开。/ 相机已关。/ 正在打开相机。 |
| 首页 | PRTS。相机未开启。开始按钮在下方，设置在右上角。 | PRTS。相机已关，开始在下方。设置在右上角。 |
| 语音开关 | 语音播报已关闭。 | 语音已关。 |

重复播报的规则同步调整：以前距离每变化 0.5 米就会再报一次，现在只有在"有障碍"和"障碍很近"之间切换时才会再报。最小间隔 2.5 秒不变。
