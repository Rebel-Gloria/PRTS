# 无障碍优化方案（只出方案，暂不实现）

日期：2026-10-28。基线：`main` `c1361ac` 加上本轮液态玻璃 UI 改动。

PRTS 的主要用户是视障和低视力人群。这份方案按"会不会让用户用不了"排优先级。
每一条都写清楚：现在代码是什么样、对用户有什么影响、建议怎么改、怎么验收。
凡是会改变交互的条目都已经单独标出来，实施前需要产品确认，避免违反"交互和算法不变"的约束。

## 现状里已经做对的

- 主页的关键控件都有 `accessibilityLabel`、`accessibilityHint` 和 `accessibilityIdentifier`。状态胶囊合并成了一个元素，标题带 `.isHeader`。
- 拍照按钮提供了 VoiceOver 自定义动作（"开始语音提问"/"结束语音提问并发送"）。双击时会把按下和松开一起触发，等于短按拍照。
- 相机画面、渐变层和装饰图标都设成了 `accessibilityHidden`。
- 液态玻璃（iOS 26 及以上）由系统自动适配"降低透明度"和"增强对比度"。主按钮保留实色底，深色文字在任何背景上都能看清。

## P0：会直接导致用不了或听不清

### A1 VoiceOver 打开时，同一件事会被说两遍

- **现状**：`ContentView.onChange(of: camera.state)` 先调用 `UIAccessibility.post(.announcement, …)`，紧接着又调用 `speechManager.speakCameraState`。VoiceOver 和 App 自带的语音会同时播报相机状态。拍照描述和空间提示用的也是 App 自带语音，会和 VoiceOver 互相打断。
- **建议**：
  1. 增加一个"播报通道"判断。`UIAccessibility.isVoiceOverRunning` 为真时，界面类状态（页面、相机状态、设置变化）只走 VoiceOver 播报；空间提示和拍照回答继续走 App 语音，并设置 `AVSpeechSynthesizer.prefersAssistiveTechnologySettings = true`，让语速和音色跟随 VoiceOver。
  2. 在 App 语音的 utterance 开始和结束时，让 VoiceOver 播报排队等待，不要互相截断。
- **验收**：打开 VoiceOver 后，主页、开始、停止、进入设置这几步，每个事件只听到一次播报。
- **注意**：这会改变播报行为，需要产品确认。

### A2 VoiceOver 和"语音控制"下无法停止

- **现状**：运行中的主按钮只能长按 1 秒停止（`stopGesture`，用 `DragGesture` 实现）。VoiceOver 用户双击会落到 `startCameraFromButton`，而它在运行状态下什么都不做。用户必须知道"双击后按住"这个手势才能停下来。"语音控制"用户和切换控制用户完全无法停止。
- **建议**：给主按钮加 `accessibilityAction(named: "停止")`，并且只在辅助技术激活时生效。普通触摸仍然保留长按 1 秒防误触的设计，触摸逻辑不变。
- **验收**：VoiceOver 下转子选"操作"→"停止"能停下；语音控制说"点按 停止"能停下。

### A3 设置页没有本地化，英文用户听到的是中文

- **现状**：`SettingsView`、`PhotoDescriptionSettingsView` 和拍照按钮的标签都直接写死了中文（例如 `Toggle("语音提示")`、`accessibilityLabel = "拍照描述"`）。`Localizable.xcstrings` 里其实已经有一套完整的 `settings.voice.*`、`settings.language.*` 中英文案，只是没有接上。
- **建议**：改用这些已有的 key，缺的再补齐。拍照按钮的三条文案（标签、提示、自定义动作名）也放进 String Catalog。
- **验收**：系统语言设为英语时，用 VoiceOver 走一遍设置页，听不到任何中文。

## P1：低视力和大字体用户

### B1 动态字体

- **现状**：标题、状态和按钮用的都是文本样式，会跟着系统字号放大。但顶栏是一个固定的 `HStack`（Logo + "PRTS" + 设置按钮），在"辅助功能超大字体"下可能互相挤压或截断。状态胶囊用了 `minimumScaleFactor(0.8)`，会把字反过来缩小。
- **建议**：
  - 顶栏改用 `ViewThatFits`：放不下时换成上下排列。
  - 去掉状态胶囊的缩小比例，改成允许换行。
  - 主按钮的 76pt 最小高度保留，同时允许按钮随文字变高。
  - 在 `dynamicTypeSize >= .accessibility1` 时隐藏开发叠加层，避免遮住主控件。
- **验收**：在模拟器 `xcrun simctl ui <device> content_size accessibility-extra-extra-extra-large` 下截图，确认没有截断和重叠。

### B2 拍照按钮几乎看不见

- **现状**：`PhotoCaptureButton` 整体 `alpha = 0.25`，160×160 的区域叠在相机画面中央，低视力用户很难发现。
- **建议**：开启"增强对比度"或"降低透明度"时，把透明度提到 0.8 以上，并加一圈玻璃底。默认外观保持不变，不挡住画面。

### B3 错误信息太小、太淡

- **现状**：权限和操作错误用的是 `.caption` 加橙色，放在状态胶囊下面，字号小，对比度也偏低。
- **建议**：改成 `.callout` 并放进玻璃面板。出现错误时额外发一条 `UIAccessibility.post(.announcement)`，确保盲人用户能知道。

### B4 只靠颜色区分信息

- **现状**：开发版图例只用颜色区分（"蓝：地面 · 红：障碍范围"）。这只影响开发版，但演示时会给色弱的观众看。
- **建议**：在叠加层里给不同类别加上不同的线型或图案。图例里同时写出线型。

## P2：体验细节

- **C1 语音控制名字和屏幕文字不一致**：按钮屏幕上写"开始"，`accessibilityLabel` 却是"开始摄像头"，语音控制下用户说"开始"可能匹配不上。建议加上 `accessibilityInputLabels(["开始", "开始摄像头"])`。
- **C2 拍照描述过程没有播报**："正在描述""正在朗读"等状态只显示在按钮下方的小字里。建议在状态变化时用 `.announcement` 播报（注意和 A1 一起考虑，避免说两遍）。
- **C3 取消按钮太小**：拍照描述时出现的"取消"按钮点击区域不到 44pt，建议设置最小 44×44。
- **C4 横屏**：iPhone 支持横屏，但主页按竖屏设计，横屏时顶栏和主按钮会挤在一起。建议要么锁定竖屏（产品决定），要么给横屏单独排布。
- **C5 减少动态效果**：可交互玻璃和转场动画在开启"减弱动态效果"时由系统处理。自定义动画要检查 `accessibilityReduceMotion`。
- **C6 触觉作为替代通道**：方向振动（PathHaptics）已经独立于语音。建议在设置里加一个"只振动、不播报"的预设，方便在嘈杂环境里使用。
- **C7 英文文案错误**：`home.settings.button` 的英文写成了 "Setting"，应为 "Settings"。

## 实施顺序和测试

1. A3 和 C7（只改文案，交互不变），同时补充 UI 测试，断言英文环境下没有中文标签。
2. B1、B3（只改布局和字号），用大字体截图做回归。
3. A1、A2、C2（会改变交互），需要产品确认；VoiceOver 实机走查的脚本写进 `PRTSUITests`。
4. 每一步都在真机上让 VoiceOver 用户或视障测试员走查；模拟器只能验证布局。

## 第二轮（2026-10-28）：超大字体布局和免按住操作

### 超大字体（辅助功能字号 AX1–AX5）

主页在 `dynamicTypeSize.isAccessibilitySize` 时换成单列布局（`ContentView.largeTextLayout`）：

- 整页可以上下滚动，主按钮固定在屏幕底部，不会被滚走。
- 顶栏保持一行：品牌标题最大到 AX1；设置按钮只显示齿轮图标（64pt 圆形），长按会弹出系统的"大型内容查看器"，显示"设置"。
- 相机未开启时的说明文字放进滚动列里，左对齐，不再叠在画面中央；装饰图标隐藏。
- 状态胶囊改成整宽圆角面板，文字可以换多行；错误信息左对齐。
- 开发版的测试指令栏改成上下排列，"发送"按钮整宽。

### 不需要按住的操作方式

| 方式 | 适用人群 | 做法 |
|---|---|---|
| 旁白 Magic Tap（两指双击） | 旁白用户 | 在主页任意位置开始或停止，不用先找到按钮 |
| 旁白/语音控制/切换控制的激活和"停止"操作 | 读屏、语音、开关用户 | 上一轮已实现，直接停止，不用按住 |
| 辅助触控（含停留控制、眼动追踪）和切换控制运行时 | 不能按住屏幕的用户 | 主按钮显示"停止"，轻点一下就停；相机运行时多一个"开始语音提问/发送语音提问"按钮，点两下代替长按提问 |
| Siri、快捷指令、操作按钮、轻点背面 | 所有人，尤其是不方便看屏幕时 | App Intents：开始、停止、描述画面。可以说"PRTS 开始"，也可以在"设置 → 辅助功能 → 触控 → 轻点背面"里绑定快捷指令 |

普通触摸的交互不变：仍然是长按 1 秒停止、按住半秒提问。

还没在真机上验证的：Magic Tap、辅助触控/眼动追踪下的轻点停止、Siri 中文短语识别。这些需要在手机上打开对应功能后手动试一次。

### 实体按键拍照描述（2026-10-28，真机已验证）

相机运行时，音量键和相机控制按钮通过 `AVCaptureEventInteraction` 触发拍照描述（`PhotoCaptureButton.applyHardwareButtons`）：按一下描述画面，按住半秒以上提问，松手发送，和屏幕上的拍照按钮一样。

- PRTS 用 ARKit 采集，在 iPhone 17 Pro Max 上实测，系统仍会把按键事件交给 App，相机控制按钮也不会跳到系统相机。
- 这期间音量键不调节音量。相机关闭或进入设置页时恢复正常。
- 开关：设置 → 拍照描述 →"音量键和相机控制按钮"（`photo.hardwareButtons`，默认打开）。系统不能只接管相机控制按钮，所以关闭后两者都不再触发描述。
