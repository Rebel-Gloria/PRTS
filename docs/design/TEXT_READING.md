# 文字识别（读文档、招牌、标签）

日期：2026-10-29。状态：已实现，单元测试通过；真机上手势、引导和超广角相机还没有实际走过一遍。

## 怎么用

- **进入**：三根手指在屏幕任意位置按住 0.8 秒。
  - 打开旁白时，多指手势会被旁白接管，App 收不到。所以主按钮上加了一个自定义操作"读文字"：在主按钮上用转子选择"操作"，上下轻扫找到它，然后双击。
- **退出**：再三指长按一次，或者轻点主按钮（旁白下是双指双击）。打开设置、切到后台、来电时也会自动退出。
- 如果避障正在运行，进入时会先说"避障已暂停"，读完或退出后自动恢复。

## 流程

1. 停掉 ARKit，改用后置**超广角**相机（`AVCaptureSession`，没有超广角的机型用广角）。超广角视野大，更容易把整页纸拍进画面；17 Pro 的超广角还能近距离对焦。
2. 预览画面每秒检查 5 次页面四角，用系统的 `VNDetectDocumentSegmentationRequest`。
3. 引导（`DocumentFraming`，纯逻辑，有单元测试）：
   - 没找到页面：说"没找到文档"；
   - 页面被画面边缘切掉：往被切掉的那一侧移，"往左移 / 往右移 / 往上移 / 往下移"。上下指手机顶部和底部的方向；
   - 两侧同时被切掉："拿远一点"；
   - 页面面积小于画面的 15%："靠近一点"；
   - 四角都在画面里："别动"。
   - 同一句提示最多每 2.5 秒重复一次；提示变了立即说。开场白播完后（3 秒）才开始提示。
4. **自动拍照**：四角持续 0.8 秒、移动不超过画面的 3% 才拍。这是为了防止误拍：移动中一闪而过的桌沿或屏幕不会被拍下。
5. 8 秒内没拍到完整页面时，说"没找到完整文档，读画面里的文字"，直接识别整个画面。这样招牌、标签这种不是整页纸的文字也能读。
6. 拍下全分辨率照片，在照片上重新找页面四角（找不到就用预览帧的四角），用 `CIPerspectiveCorrection` 拉正，再用 `VNRecognizeTextRequest`（精确模式，简体中文、繁体中文、英文）识别。
7. 文字先按从上到下分行，同一行内从左到右排；中文行直接拼接，其他行之间加空格。用拍照描述的朗读声音读出来。

## 为什么不用内嵌模型

MiniCPM-OCR 1.0 要额外下载约 1.5 GB，速度也没有实测过。Apple 的 Vision 在手机上本地运行，不用下载、不上传图片，测试中识别一页约 0.7 秒。复杂版面（多栏、表格）的阅读顺序可能出错，这一点以后再看要不要改进。

## 代码

- `PRTS/TextReading/DocumentFraming.swift`：引导和自动拍照策略。
- `PRTS/TextReading/TextRecognizer.swift`：找页面、拉正、识别、排阅读顺序。
- `PRTS/TextReading/TextReadingSession.swift`：超广角相机和整个流程。
- `PRTS/TextReading/ThreeFingerHold.swift`：装在窗口上的三指长按识别器，不拦截其他触摸。
- 测试：`PRTSTests/DocumentFramingTests.swift`、`PRTSTests/TextRecognizerTests.swift`。后者会画一页纸放在深色背景上，在真机上跑完整的找页面、拉正、识别流程。

## 待验证

- 真机：三指手势会不会和拍照按钮、主按钮的按住停止冲突；停掉 ARKit 后立即打开超广角相机是否稳定；恢复避障是否正常。
- 引导用语和方向是否容易理解，"往上移"是否符合直觉。
- 真实文档（书页、说明书、快递单、菜单）的识别效果和阅读顺序。
