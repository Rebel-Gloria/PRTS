# 本地视觉模型可行性：MiniCPM-V 4.6（iPhone 17 Pro Max）

日期：2026-10-28。状态：**Q4_K_M 和 Q5_K_M 都已在 iPhone 17 Pro Max 上实测（见"真机实测"一节）。**下文标"估算"的是测之前的纸面数字，以实测为准。

## 结论

- **可行，但只适合做"拍照描述"的离线/隐私选项，不能进入避障链路。** 避障要求 10 Hz、毫秒级、确定性的输出；0.8B 的视觉语言模型一次回答要一两秒，而且会编造内容。
- 推荐组合：**Q4_K_M 语言模型（505 MB）+ F16 视觉模块（1.03 GB）**，合计约 1.6 GB 权重。
- 估算体验：模型已加载时，按下拍照到开始朗读约 **1.5–2.5 秒**，与现在的云端（取决于网络，通常 2–5 秒）相当或更快；首次加载另加 1–2 秒。
- 最大的未知数是**描述质量**，其次是**内存峰值**。两者都必须在这台 17 Pro Max 上实测。

## 真机实测（Q4_K_M / Q5_K_M + F16 视觉模块，2026-10-28）

- 环境：iPhone 17 Pro Max，Release 构建，llama.cpp 620d2225（Metal，全部层放 GPU），贪心解码，最多 128 个 token，上下文 2048。
- 输入：5 张 DIAG 帧（20–35 KB 的低分辨率截图，画面上叠着调试文字），最后再跑一遍第一张，作为热启动对照。
- 提示词：现在的 `PhotoChatProtocol.prompt`，关闭思考模式。
- 复现：`PRTSTests/LocalVLMBenchmarkTests`。需要链接 bench 库，模型放在 App 的 `Documents/vlm`，结果写到 `Documents/vlm/result-<量化>.json`。

### 产品分辨率的实拍照片（Q5_K_M，2026-10-29）

- 输入：3 张 OnePlus 实拍照片（自行车与台阶、健身房地面、健身凳和 15KG 杠铃片），按 `PhotoImageEncoder` 缩到长边 1280（960×1280）。提示词是现在的 `PhotoChatProtocol.system`。
- 复现：`PRTSTests/LocalVLMBenchmarkTests/photosQ5()`，照片放 `Documents/vlm/photos`。每张跑两遍，第二遍是热启动。照片里有路人，没有提交进仓库。

| 项（热启动） | 实测 |
|---|---:|
| 每张图的视觉 token | 126（DIAG 小图是 63） |
| 视觉编码 | 455–462 ms |
| 预填充 | 约 77 ms |
| 首个 token | 约 570 ms |
| 生成 14–29 个 token | 约 170–350 ms，81–87 token/s |
| 总耗时 | 0.73–0.88 s |
| 进程内存峰值 | 1.54 GB |

- **在产品分辨率下，最大的一块耗时是视觉编码，占约 60%。**语言部分（预填充加生成）合计约 0.25–0.43 s。
- 回答（热启动和冷启动逐字相同）：
  - 自行车："很近有一辆自行车，路面有台阶，正前方是行人。"没说台阶是向上的。
  - 健身房地面："很近有一台健身器材，右边有一个大风扇。路面平整，没有台阶或坡。"漏了左边贴得最近的椅子腿。
  - 健身凳："很近有一个黑色的重量块，上面写着"15KG"。……左边有健身器材。"读对了字，但没说正前方的健身凳。
  - 没有编造和方向说反，但有漏报。

结论更新：

- **速度远好于估算。**
  - 热启动时，按下到出完整答案约 0.4–0.7 秒，首个 token 约 0.25 秒，比云端（2–5 秒）快得多。
  - 冷启动（加载 1.3 秒 + 首张 1.6 秒，含 Metal 着色器编译）约 3 秒，可以在进入拍照页或 App 启动后预热。
- **内存比估算低。**
  - 峰值 1.52 GB，估算是 2.6–3.1 GB。
  - 原因：权重通过 mmap 映射，干净的文件页不计入 `phys_footprint`，而系统按 `phys_footprint` 判断是否杀掉 App。
  - 还要测同时开着 ARKit 时的总峰值。
- **质量是主要问题。**
  - 小模型会复读提示词，比如"最重要的人或物在中间"，描述也空泛。
  - 它会把 DIAG 叠加的调试文字（"B3 idx 185 …"）当成画面里的字读出来。
  - 但这批输入是低分辨率的调试截图，不能代表真实拍照。质量必须用真实相机照片重新评估，并给小模型单独写一份提示词。

## 文件夹里有什么

| 文件 | 大小 | 用途 |
|---|---:|---|
| `MiniCPM-V-4.6-Q4_K_M.gguf` | 505 MB | 语言模型，内存优先 |
| `MiniCPM-V-4.6-Q5_K_M.gguf` | 551 MB | 语言模型，质量优先，只比 Q4 大约 49 MB |
| `MiniCPM-V-4.6-Q8_0.gguf` | 774 MB | 语言模型，8 位 |
| `mmproj-MiniCPM-V-4.6-F16.gguf` | 1.03 GB | 视觉模块（SigLIP2-400M），三种语言模型共用 |

- 模型：SigLIP2-400M 视觉编码 + Qwen3.5-0.8B 语言模型，Apache-2.0 许可，可以商用。
- 导出配置：448 像素、16 倍视觉压缩、1 个切片，因此一张图约 64 个视觉 token；关闭思考模式。
- 文件夹自带的验证只在服务器上做过：24 个合成样本的冒烟测试，以及 RTX 5090 显存。**报告写的目标机型是 iPhone 15 Pro，从没在手机上跑过。** 服务器显存数字不能换算成手机内存。

## 性能估算（iPhone 17 Pro Max，A19 Pro，12 GB 内存）

| 阶段 | 估算 | 依据 |
|---|---|---|
| 冷加载（读 1.6 GB + Metal 初始化） | 1–2 s | 闪存顺序读取加着色器编译；可在进入拍照页时预热 |
| 视觉编码（448 px，1024 个 patch） | 0.2–0.5 s | 约 0.8 TFLOP，按 GPU 有效算力 30–50% 估算 |
| 预填充（约 100 个 token） | < 0.1 s | |
| 生成（两句中文，约 40–60 个 token） | 0.6–1.5 s | 0.8B Q4 受内存带宽限制，估算每秒 40–80 个 token |
| **按下到出完整答案（已加载）** | **约 1.5–2.5 s** | 边生成边朗读时，首句更早出声 |

## 内存

| 项 | 估算 |
|---|---:|
| PRTS 现在的峰值（实测 DIAG） | 0.73 GB |
| Q4 + F16 视觉权重 | 1.6 GB |
| 2K 上下文 KV 缓存与递归状态 | 约 40 MB |
| Metal 计算缓冲、图像缓冲 | 0.2–0.4 GB（估算） |
| **合计峰值** | **约 2.6–3.1 GB（估算）** |

- 12 GB 的机器装得下，但单个 App 的内存上限由系统决定，可能需要申请 `increased-memory-limit` 权限，一定要实测 `phys_footprint` 峰值。
- 如果内存紧：先把视觉模块从 F16 量化到 Q8（约 0.55 GB，可省 0.5 GB），需要先验证质量；或者闲置 30 秒后卸载模型。
- 同样的方案搬到 8 GB 的 iPhone 15 Pro 上会紧张得多，那台机器要单独测。

## 对避障的影响

- 模型只在按下拍照时运行 1–2 秒，属于短时 GPU 峰值。避障分析主要在 CPU 上（p95 约 4 ms），17 Pro Max 有 LiDAR，不走 Core ML 深度，所以直接冲突小。
- 可能受影响的是画面渲染：推理期间可能掉帧。无画面模式下不受影响。
- 发热：偶尔用问题不大；连续拍照要看真机测得的持续功耗。
- 必须实测：推理期间避障分析帧率是否仍保持 10 Hz、有没有丢帧。

## 质量和安全

- 0.8B 模型的描述能力明显弱于现在的云端模型（qwen3.8-flash / deepseek-flash）。它更容易**说错东西**，比如数错物体、读错文字、编造不存在的物体。对盲人用户来说，说错和说漏一样危险。
- 上线前要用 PRTS 自己的真实照片做对比评测，例如 dev capture 保存的室内、夜间、街道帧：本地模型和云端模型各描述一遍，人工判断对错，统计"说错"和"说漏"。
- 只用作描述，绝不拿它的输出去做避障判断。

## 集成方式

- 推理引擎：llama.cpp（含多模态库 mtmd，可用 Metal 加速），编成 XCFramework 接进工程。也可以参考官方开源的 iOS 示例 `OpenBMB/MiniCPM-V-edge-demo`。
- 接入点：做成拍照描述的第 4 个服务商"本机（离线）"。刚做好的 `PhotoChatProvider` 抽象正好可以接：`describe(jpeg, text)` 返回字符串，可以流式输出。
- 分发：**不要打进 App 包**（1.6 GB）。在设置里"下载离线模型"，下载后校验 SHA-256（文件夹里有 `SHA256SUMS.txt`），存进 Application Support，并标记为不备份到 iCloud。
- 仓库：模型文件夹已加入 `.gitignore`，不会被提交。

## 下一步：真机基准（第 1、2 项已完成，见上）

做一个最小的基准测试，在这台 17 Pro Max 上测：

1. Q4 和 Q5 的冷加载、视觉编码、预填充、生成速度（每秒 token 数）；
2. `phys_footprint` 峰值，以及有没有被系统杀掉；
3. 同时开着 ARKit 避障时，分析帧率和发热；
4. 用 20–30 张 PRTS 实拍照片，对比本地模型和云端模型的描述质量。

成本：编译 llama.cpp 的 XCFramework 是一次性的，在这台 8 GB 的 M1 上大约 10–20 分钟，要错开 Astra 的编译。
